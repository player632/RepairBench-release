# 我们自己那套后台管理系统，最近毛病有点多

我们内部用的是一套 Vue 3 + TypeScript + Vite 的后台管理模板，浏览器打开就能用。左边一整条可以收起／展开的菜单栏（首页、几个「例子」演示页、一个 404 页面，另外还有两项点了是会跳到外面去的），顶上一条工具栏：折叠按钮、面包屑、一个搜索框，右边是头像和它下拉出来的菜单。主区域按页面不同：首页是一大片自己写的表单控件（输入框、按钮、勾选框、下拉、开关、弹层、提示条这些），旁边挂着一块能改样式、还能存成几套预设的预览区；「例子」底下有请求演示页、组件演示页，还有一个用 tsx 写的卡片轮播页。整套东西**没有任何真的后台服务**，登录是在浏览器里假装的，数据也都是随包带的、固定的、每次都一样的。最近不知道是升级还是谁动过，好几个地方不对劲。我们组没人会写前端，只能把眼睛看到的现象照实说出来，麻烦你们从头查一遍、修一修。

**先把话说在前面**：下面这些只是我们几个人平时用得到的部分，**并非所有缺陷都有报告提及**。有些毛病我们可能压根没注意到，或者不知道该怎么形容，甚至根本不知道那是个毛病。所以请你们自己把整套东西从里到外过一遍，别只盯着我列出来的这几条改；修别的问题时弄坏的行为，同样会算在你们头上。

## 我们确实碰到的问题

1. 首页那个「侧边菜单栏宽度」的输入框，我填了个 999 想试试宽的，过了半秒它自己跳回 160 了；反倒填比 160 小的数（比如 30）它不动，也不给我拦回去。

2. 浏览器标签页上的标题不跟着页面走了：不管点到哪一页，标题一直是刚打开时那一个，以前是会变成当前页面名字的。

3. tsx 示例页那个卡片轮播，点「下一张图片」点到第三张就再也翻不动了，按钮还是能点，就是最后一张永远看不到。

4. 首页「显示历史记录标签」那个勾选框，点了没反应，上面那排历史标签一直挂在那儿关不掉；其它几个开关倒是好的。

5. 左边菜单的高亮整个反了：当前这一页那一项不亮，其它十来项反倒全亮着，看着像十几处都选中了。

6. 顶上的面包屑整条没了，一个层级都不显示，就剩空白一条；页面本身是好的，能正常用。

7. 右下角那个「返回顶部」的圆按钮，页面刚打开、明明还在最顶上，它就已经显示在那儿了；以前是要往下滚过一屏才出来的。


## 另外两件我们拿不准算不算毛病的事

（这两条有可能是我们自己想多了、本来就是设计如此。请你们先判断是不是真毛病，再决定要不要动；如果本来就是正常行为，把它「修好」反而会把别的东西弄坏。）

8. 这系统是不是该有个「发现新版本，是否更新」的提示？我们等了半天也没见它弹出来，是不是版本检查坏了？

9. 左边菜单里「百度一下」和「项目地址」这两项，点了不是在页面里打开，而是直接弹出一个新标签页跑出去了，是不是路由坏了？


## 环境说明

- 这个系统跑起来**不需要外网，也不需要任何真的后台服务**：账号、菜单、页面里的数据全是随包带的本地演示数据，「登录」这件事在浏览器里就被接住了，一个网络请求都不会发出去。我们这边是拔了网线试的，页面自己没往外发过请求，也没弹新窗口、没跳到别的站点。头像和几张插图本来是从外面几个图床拉的，我们已经统一换成了一张本地的透明占位图；有些小图标本来是从外面的图标服务现拉的，也已经换成了本地的占位图形。所以断网照样能跑、排版和功能都不受影响，只是看不到那些图和图标而已。
- **打开就是已经登录好的状态**（我们内部配的免登录），不用去找账号密码，也没有图形验证码那一套。要是你们看到登录页，说明是环境没起来，不是缺陷。
- 地址栏里的地址是 `#/...` 这种形式（井号后面跟路径），刷新或者直接从某个地址进去都应该能到对应页面。
- 浏览器窗口是按 **1440×900** 试的，桌面尺寸；换个宽度有些地方会换成另一套排版或者另一套事件，现象可能不一样。
- 每一项检查都是从一个**全新的页面**重新开始的：上一屏点过的按钮、收起或展开过的菜单、改过的设置、存过的预设都不会带到下一屏，也不会有上一次跑剩下的本地存储。
- 页面里挂了一小段给自动化验收用的**只读探针**（记录页面有没有起来、有没有往外发请求、有没有报错），请**不要删掉它、不要改名、也不要让它去读写业务状态**；我们看不出你们动了它，但验收会。
- 上面全是使用者视角的原话。我们不会去翻代码，也没本事告诉你们原因在哪儿、该改哪个文件；哪几条是真毛病、哪几条本来就是设计如此（第 8、9 条就有可能是我们自己想多了），得你们自己判断。
- 我们这边是**中文环境**（zh-CN，时区 Asia/Shanghai）。你们核对现象时请**以数值本身、行／项的数目、以及某个东西在不在为准**，不要以某句提示文案的措辞、日期分隔符或者千分位写法为准；跟时间有关的判断也请用「相对现在」的说法，别写死具体年份。
- 有几处毛病是**要等一会儿才看得出来**的（比如某个输入框改完过半秒才自己回弹、某个提示条挂一会儿就自己消失、某次点击要等一下才落地），请别只在页面刚加载那一瞬间看一眼就下结论。
- 改完以后整套东西还得能**照常打包出来**：别为了绕过现象把功能整块删掉、把控件去掉、把菜单项删掉、把某段代码注释掉，也别写死一个常数或者一个固定返回值来让现象「看起来好了」。
- 也**别去动那些跟现象无关的东西**。菜单里那两项本来就该开新标签页的、还有那个从来不弹的版本提示，都是它本来的样子；动了反而算你们弄坏的。
