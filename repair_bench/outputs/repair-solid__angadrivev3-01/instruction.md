# 修复任务：AngaDriveV3（Go 后端 ＋ SolidJS 前端的自建网盘）

你面对的是 **AngaDriveV3** 的源码：一套自己托管文件的网盘应用（远程文件存储，
上游自己的说法是「主要为速度、性能和用户体验而做」）。仓库分两半：Go 写的
后端（`accounts/`、`database/`、`endpoints/`、`globals/`、`info/`、`previews/`、
`requestHandler/`、`runners/`、`tester/`、`uploads/`，入口是 `main.go`）和一个
单页前端（`web/`，SolidJS ＋ TypeScript，vite 打包，样式是 tailwind）。前后端
之间是一条 WebSocket 长连接：登录、拉文件列表、拉合集列表、上传、删除、排序
都走这条连接；登录态与用户资料存在浏览器本地的存储里。左侧导航一共五项：
Home、Files、Collections、GitHub、Account。页面一共这几张：

- **首页**（`/`）：顶部是 AngaDrive 的大标题和一句副标题；下面一排三个开关卡
  （Caching、File Previews、Ultra Secure，每张卡上写着 `Default: Enabled` 或
  `Default: Disabled`）；再下面是「Site Activity Over Past Month」的图表，以及
  Ram Usage、CPU Usage、Space Used (GB) 三块读数，和 Users 与 Files Hosted
  两个统计块。
- **我的文件**（`/my_drive`）：标题 My Files。工具条上有一个搜索框（占位文字是
  「按名字或路径找文件」那一句）、一个标签写作 Sort By 的排序下拉（六个选项：
  Time: Newest first、Time: Old first、Name: Alphabetical、Name: Reverse
  alphabetical、Size: Largest first、Size: Smallest first），以及上传入口。
  主体是一列文件卡片：每张卡上半是预览区（图片／音频／视频，取不到预览时是
  一个灰色占位图标），下半是文件标题和四行读数——Type、Uploaded Name、
  Timestamp、Size；卡片底部一排图标按钮：眼睛（打开查看链接）、复制链接、
  下载、转换、删除、选中。列表为空时会显示「你上传的文件都会出现在这里」那
  一句空态提示。
- **我的合集**（`/my_collections`）：标题 My Collections。主体是一列合集卡片，
  每张卡有标题和 Size、File Count、Folder Count、Editors 四行读数，底下两个
  操作按钮。
- **合集内页**（`/collection/*`）：进到某个合集之后的文件浏览，带层级导航，
  以及「加文件」「加文件夹」两个弹窗入口。
- **账户**（`/account`）：没有登录态时是登录／注册表单；登录之后是账户面板，
  上面三块读数 Space Used、Files Hosted、Collections，下面是账户资料和一个
  标着 Danger Zone 的红色区，里面有一个 Log Out 按钮。

工程就在当前工作区里，完全离线：判分器会自己在 `web/` 里把前端依赖复原好、
跑 `npm run build` 把产物打到 `web/dist/`，然后伺服 `web/dist/`、用真实浏览器
驱动界面（这一株的打包配置把前端全部塞进一个自包含的产物里，`web/dist/` 只有
寥寥几件）。**后端不会启动**——判分环境用一份确定性的离线桩顶替那条 WebSocket
长连接与后端接口，桩里的数据是写死的夹具（默认那一组是 5 个文件 ＋ 2 个合集；
判分时会按检查点切到别的夹具组，最大的一组是 6 个文件），所以你看到的每个
读数都是可复现的，不会因为跑的时刻不同而变。仓库根目录**没有** `package.json`，
所有 npm 命令都要在 `web/` 里跑。没有任何网络访问。

QA 收集了一批用户报告，下面基本按用户原话照录——带着他们自己的操作步骤、
噪音和猜测。把它们当起点，不要当诊断结论：

- 大部分报告描述的是真实、可复现的缺陷，每一枚都有自己的根因；根因所在的
  文件未必是症状表现出来的那个地方，同一个症状也可能有好几个候选解释。
- 至少有一条报告描述的其实是**本来就该这样**的行为。动手改之前先自己复现、
  先鉴别：把不是缺陷的东西「修」掉，一样算你弄坏了行为。
- **并非所有缺陷都有报告提及**，报告里没有全部列出。没被提到的缺陷同样在
  判分范围内；你在修别的问题时顺手弄坏的行为，也一样算你的失分。

报告如下，顺序没有意义：

1. 「『我的文件』里每张卡片的 Size 都比我印象中大一点点：一个 5 MB 的文件写成
   5.12 MB，几百个文件都是这个调子，像是统一涨了百分之二。看着像后端把容量
   算错了、或者磁盘统计口径变了；其实合集页那张卡的 Size、还有账户页那句
   Space Used 也跟着一起变了，三处数字都对不上我本地的实际大小、又都只差这么
   一点，我一开始还以为是同一批文件被重复计了一次。1 KB 以下的小文件读数倒是
   正常的。」

2. 「我所有的 PDF 文件，Type 那一栏都从 Document 变成了 Unknown，乍一看像类型
   识别整个坏掉了；可再一看，.txt 和 .docx 那些还是照常显示 Text Document，
   .mp4 还是 Video，只有 PDF 这一类整个掉出去了。」

3. 「我在『我的文件』里删掉一个文件，点了确认之后，列表里居然只剩下那一个被我
   删掉的文件，其他几十个全不见了；刷新一下页面（重新拉一次列表）又都回来了。
   看着像删除操作把整个盘清空了，其实数据一个都没丢——是删除之后本地那一次
   列表更新，把该留下的全过滤掉了。」

4. 「名字里带空格的文件，我把那个查看链接复制出来粘到别处，只有第一个空格变成
   了 %20，后面的空格还是原样的空格，链接一断一断的；名字里没有空格、或者只有
   一个空格的文件倒是都正常。看着像复制功能把链接截断了，其实是转义只做了一
   遍。」

5. 「『我的文件』的排序整个反了：我选 Time: Newest first，出来的是最旧的在最前
   面；改选 Name: Alphabetical，出来的是倒着字母序。六个选项我一个个试了，全
   都是反的，像是升序降序的标签被贴错了位置。看着像下拉框的文案和实际比较器
   对不上号，其实那六行映射本来就是故意写成三对一模一样的——真正决定方向的
   是后面那一句反转闸门。」

6. 「搜索框几乎搜不出东西了：我输入文件名的一部分，列表直接空掉，变成『没有
   文件』那个提示；可我把搜索框清空，所有文件又都在。试着输入一个同时出现在
   名字和路径里的词，居然能搜出来一条。看着像文件列表丢了，其实列表一直是全
   的，坏的是搜索的匹配条件。」

7. 「我有一个合集名字正好 11 个字符，卡片标题本来显示得完完整整，现在被截成了
   前 9 个字符加三个点——加起来 12 个字符，比原名还长。看着像标题渲染出了
   bug、平白多塞了省略号，其实是『要不要截断』的门槛少算了一位，而截断长度没
   跟着改。」

8. 「离线跑起来以后，/my_drive 上所有文件的预览图都是灰的占位图标，一张真图都
   出不来；卡片上那个眼睛图标的链接指向 http://localhost:8080/…，可我们这个
   环境里 8080 上什么都没有，等于死链。是不是资源地址算错了、应该走同源相对
   路径？想先确认这是漏配了环境变量还是有意为之——如果是有意的我们就不动
   它。」

9. 「把浏览器窗口拉到 700px 左右宽，首页还是桌面版布局，可一进 /my_drive 就变
   成移动版壳子了；同一个应用里两套断点，看着像响应式坏了。是不是应该统一成
   一套门槛？」

## 约束

- 本次会话里不要自己跑工程的 build、dev server 或测试来自验；另有判分器会
  重新构建并用真实浏览器驱动界面。请把力气放在读代码、找根因上。
- 修复要落在根因上，不要为了绕过某条报告而加特例判断、加开关或改判分面。
- 不要改判分链路会读的那些探针与离线桩文件，也不要新增全局标志或把状态写进
  浏览器存储／URL 来「让读数变对」：判据里专门有一组检查点在看这些残留。
