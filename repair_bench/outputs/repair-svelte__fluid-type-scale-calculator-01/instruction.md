# 我们那个流式字号计算器，最近好几处不对劲

我们设计组天天用的是一套网页版的「流式字号计算器」：左边是一整排表单（最小/最大字号、最小/最大屏幕宽度、两个模块化比例尺、要生成几档字号、以哪一档为基准、CSS 变量的前缀、小数位数、几个开关——用容器宽度还是视口宽度、要不要额外生成一套兼容老浏览器的写法、用 rem 还是 px、以及预览区用哪个字体、预览哪段文字、预览多宽），右边实时给出两样东西：一段可以直接复制走的 CSS（一串自定义属性，每个都是「最小值 / 中间那段随宽度变化的流式表达式 / 最大值」这种三段式写法，外加两段给不支持新语法的浏览器用的兜底），以及一张七行的表格，把每一档字号的最小值、最大值、当前宽度下真正渲染出来的值、和一行按那个字号排出来的示例文字都列出来。表单上方还有一组常用的比例尺预设（比如「Minor second」「Major third」「Perfect fourth」这些），点一下就填进两个比例尺输入框。改任何一个输入，地址栏都会跟着更新，我们靠复制地址栏里的链接互相分享配置。

最近升级完之后好几个地方不对劲。我们组没人会写前端，只能把眼睛看到的现象照实说出来，麻烦你们从头查一遍、修一修。

**先把话说在前面**：下面这些只是我们几个人平时用得到的部分，**并非所有缺陷都有报告提及**。有些毛病我们可能压根没注意到，或者不知道该怎么形容，甚至根本不知道那是个毛病；有些毛病还被别的毛病盖住了，得先修掉外面那层才看得见。所以请你们自己把整套东西从里到外过一遍，别只盯着我列出来的这几条改；修别的问题时弄坏的行为，同样会算在你们头上。

## 我们确实碰到的问题

1. 生成出来的 CSS 里，每个变量的中间那段是个**负数**：`--fs-base: clamp(1rem, -0.34vi + 1.09rem, 1.19rem)`。屏幕越宽字反而越小，一直缩到最小值就不动了；下面那张表的 Rendered 一列也不跟着宽度走了。

2. 勾上「Use container inline size (cqi) instead of viewport width」以后，生成出来的变量里单位还是 `vi`，一点没变成 `cqi`；可是上面那两行注释和 `@supports` 里的探测又确实写着 cqi/container queries，自相矛盾。

3. 把「Variable prefix」从 fs 改成我们设计系统用的 sp，右边生成出来的变量名还是 `--fs-sm`、`--fs-base`……完全不理我们填的前缀。

4. 生成的 `clamp()` 看着数字都对，但贴到页面里字号就固定在最大值不动了，屏幕拉宽拉窄都一样。仔细看是三个参数的**顺序**不对：中间那格放的是最大值，最后那格才是带 `vi` 的流式表达式。

5. 「Include fallback CSS」这个勾选框点了会自己弹回去：勾上以后立刻又变回没勾，右边生成的 CSS 里始终没有那两段 `@supports`（听说应该有支持 clamp 和不支持 clamp 两套写法）。别的勾选框都正常。

6. 拖动 Preview 那一栏的宽度滑杆，下面表格最右边「Preview」那格的字确实变大变小，可它左边「Rendered」那格的数字死活不动，一直是最大宽度时的值。两个数字明显对不上。

7. 改完任何一个输入框，地址栏要等好久（感觉有三四秒）才更新，以前几乎是马上就跟着变的。我们靠复制地址栏链接分享配置，现在经常复制到还没更新的旧链接。

## 另外两件我们拿不准算不算毛病的事

8. 生成出来的变量里，中间那段写的是 `0.34vi + 0.91rem`，单位是 `vi`。我们一直以为是 `vw`（viewport width），是不是当初写代码的人把 vw 打错成 vi 了？要不要我们全局把 vi 改回 vw？

9. 把「Use rems instead of pixels」那个勾去掉以后，下面的「Rem value (pixels)」输入框整块就消失了。是不是隐藏逻辑写反了、或者那块 UI 坏了？要不要我们让它一直显示出来？

## 环境说明

- 这个工具跑起来**不需要外网，也不需要任何后台服务**：所有数值都是浏览器里根据表单当场算出来的。我们这边是拔了网线试的，页面自己一个外部请求都没发出去，也没有弹新窗口、没有报错；原来那个「换个预览字体就去外部字体服务取一份样式表」的行为已经被关掉了，所以任何「联网去取」的修法在这儿都不会生效，也不应该生效。
- 浏览器窗口是按 **1440×900** 试的，桌面尺寸，语言 en-US、时区 UTC。上面每一条现象都是在这个尺寸下看出来的，换个尺寸现象可能不一样。
- 每一项检查都是从一个**全新的页面**重新开始的：上一屏点过的开关、拖过的滑杆、填过的输入框都不会带到下一屏，本地存储里也不会留着上一次跑剩下的东西。所以「靠记住上次的状态蒙对」这种修法不管用。
- 页面里挂了一小段给自动化验收用的**只读探针**（记录页面有没有起来、有没有往外发请求、有没有报错、有没有被谁偷偷写进本地存储），请**不要删掉它、不要改名、也不要让它去读写业务状态**；我们看不出你们动了它，但验收会。
- 上面全是使用者视角的原话。我们不会去翻代码，也没本事告诉你们原因在哪儿、该改哪个文件；哪几条是真毛病、哪几条本来就是设计如此（最后那两条就有可能是我们自己想多了），得你们自己判断。
- 改完以后整套东西还得能**照常打包出来**，别为了绕过现象把功能整块删掉、把表单控件去掉、把数字写死成常量、或者按检查项做特判——那样我们会当成新毛病算在你们头上。一共是 12 个缺陷，我们只报了 7 条，剩下的自己找。
