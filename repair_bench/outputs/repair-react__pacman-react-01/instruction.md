# 我们那个吃豆人小游戏站点，最近好几处不太对劲

我们内部用的是一个浏览器里就能打开的吃豆人小游戏／素材演示站点，不用登录、也没有后台服务，东西都在本机。左边一列菜单有四个入口：Home（真正能玩的那一页）、Sprites（精灵图鉴）、Maze（迷宫网格）、Way Finding（寻路演示）。游戏页上是整个盘面：小豆子、四个大豆子（能量豆）、吃豆人、四只鬼，右上角有分数和剩余命数的小图标；盘面底下还有一块开发用的调试面板，能让游戏暂停／继续、能给吃豆人和鬼发事件（有个 Eat 按钮）、四只鬼各自有冻结开关，还有张表实时显示每只鬼的坐标和状态。Sprites 页是几行精灵展示，有的行是循环动画、有的行是静态排开；Maze 页可以把鼠标移到格子上看坐标读数；Way Finding 页是先点起点再点终点、然后把寻路一段一段画成箭头。最近升级完之后，好几个地方不对劲。我们组没人会写前端，只能把眼睛看到的现象照实说出来，麻烦你们从头查一遍、修一修。

**先把话说在前面**：下面这些只是我们几个人平时用得到的部分，**并非所有缺陷都有报告提及**。有些毛病我们可能压根没注意到，或者不知道该怎么形容，甚至根本不知道那是个毛病；还有的要先在页面上走一段、按某个键、把鼠标移开、或者把时间拖过去才会露出来，光看一眼是看不出来的。所以请你们自己把整套东西从里到外过一遍，别只盯着我列出来的这几条改；修别的问题时弄坏的行为，同样会算在你们头上。（Not every defect is necessarily mentioned in the reports. Behaviors you break while fixing other things still count against you.）

## 我们确实碰到的问题

1. 游戏那一页按空格本来能暂停／继续。可是只要我们先去别的页（比如迷宫那页）再回到游戏页，空格就没反应了：按下去既不暂停也不继续，再按几下也没用，只有整页刷新才恢复。来回走几次都一样。

2. 左边那列菜单（Home / Sprites / Maze / Way Finding）的高亮，在我们用浏览器后退键回到上一页之后就不跟着走了：页面内容确实回去了，菜单上还高亮着刚才离开的那一项。用鼠标直接点菜单倒是正常的。

3. 游戏盘面最下面那一行的小豆子整行不见了，数下来比开局少了三十来颗；上面那些行都还在，四个大豆子也都在。以前刚开局是满盘的。

4. 右上角代表剩余命数的那两个小图标叠在一起了，看着像一个；以前是两个分开的、隔着一段距离。命数本身显示是对的。

5. 盘面上的精灵（吃豆人、鬼、豆子）看着都往左上偏了一点，跟迷宫的墙对不齐；可是我们量过它们的位置数字，读数是对的，所以一开始还以为是自己的错觉。

6. Sprites 那页有几行动画演示，本来是一直循环播放的（那几个帧轮着来），现在停在其中一帧不动了；同一页里那些静态展示的行还是好的。

7. 吃到大豆子（能量豆）之后，鬼变成可以被吃的那段时间长得离谱：我们等了快一分钟还没结束，面板上那个剩余时间的读数也是个很大的数。以前几秒就恢复追逐了。

## 另外两件我们拿不准算不算毛病的事

（这两条有可能是我们自己想多了、本来就是设计如此。请你们先判断是不是真毛病，再决定要不要动；如果本来就是正常行为，把它「修好」反而会把别的东西弄坏。）

8. 迷宫那一页（Maze）的格子看着比周围的墙偏出去几像素，像是没对齐。这个是不是排版坏了、还是本来就这样？

9. 另外我们组里有人说，这站点的页面上本来应该能看到一个帧率（FPS）数字，可是我们在四个页面上都找遍了，一个都没有。是不是哪一块没做完？

## 环境说明

- 这个站点跑起来**不需要外网，也不需要任何后台服务**。我们这边是拔了网线试的：四个页面一个外部请求都没发出去，没有弹新窗口、没有跳登录、没有跳第三方站点。
- 浏览器窗口是按 **1440×900** 试的，桌面尺寸；换个宽度有些地方会换成另一套排版，现象可能不一样。
- 每一项检查都是从一个**全新的页面**重新开始的：上一屏点过的按钮、改过的数值、开过或关过的开关都不会带到下一屏，也不会有上一次跑剩下的本地存储。
- 页面里挂了一小段给自动化验收用的**只读探针**（记录页面有没有起来、有没有往外发请求、有没有报错、本地存储里有哪些键），请**不要删掉它、不要改名、也不要让它去读写业务状态**；我们看不出你们动了它，但验收会。
- 这游戏本身有随机性：鬼在被吓到的那段时间里是随机选路的，所以涉及「鬼往哪走、走到第几格」的现象，我们都是在调试面板上把该冻的冻住、该暂停的暂停之后再看的。你们复现的时候大概也得这样，否则每次看到的都不太一样。
- 上面全是使用者视角的原话。我们不会去翻代码，也没本事告诉你们原因在哪儿、该改哪个文件；哪几条是真毛病、哪几条本来就是设计如此（最后那两条就有可能是我们自己想多了），得你们自己判断。
- 判分由验收方完成，**作答期间请不要自己去跑项目的构建或测试命令**来自验；改完以后整套东西还得能**照常打包出来**（该过的类型检查和构建都得过），别为了绕过现象把功能整块删掉、把某个数值写死、把盘面或精灵换成一行静态文字、把开关改成不可点、或者只在我们看得见的那一处写个特判——那样我们会当成新毛病算在你们头上。
