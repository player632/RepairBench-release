# 修复任务：TailAdmin Vue 后台管理面板（seed: vue-tailwind-admin-dashboard）

## 1 · 你拿到的是什么

一个 Vue 3 + Vite + Tailwind CSS v4 的后台管理面板模板：左侧导航栏、顶部工具栏、电商首页仪表盘（KPI 卡片、图表、地域占比、最近订单表格），外加日历、用户资料、表单、表格、图表与若干 UI 元素示例页。路由是 history 模式。

这棵树在交付给你之前被人为弄坏了：**代码里潜伏着 12 处缺陷**，分散在 12 个不同文件中，每一处只改动了很少的几个字符或一行逻辑。没有编译错误，页面也不会白屏——所有缺陷都表现为**行为或视觉上的错误**。

构建与自检方式（离线，无后端、无外网）：

- 安装依赖：`npm install --no-audit --no-fund`
- 构建：`npm run build`（含类型检查，产物目录 `dist`）
- 本地伺服：`node evaluation/serve_static.mjs --dir dist --port <port>`（**保留 SPA 回落**，因为有 history 深链）

## 2 · 验收方式

验收完全由浏览器检查点构成，共 **29** 条，跑在 1280x720 的无头 Chromium 上：

- **12 条**当前是红的（对应 12 处缺陷的可观测症状），修好后必须**全部转绿**；
- **17 条**当前是绿的，是「不许弄坏」的领地守卫与既定行为守卫，必须**保持**绿色。

得分 = 100 ×（红转绿比例）×（守卫保持绿比例），两者任一不满即 reward = 0。也就是说：**把正常行为"修"坏，或为了讨好某条报告去改动模板的既定行为，都会直接把分数打成 0。**

## 3 · 用户报告（9 条）

**并非所有缺陷都有报告提及。** 下面 9 条里，前 7 条确实对应缺陷；另有条目描述的其实是模板的**既定行为、并不是缺陷**——请自行判断，不要为这类条目改动正常行为。还有一部分缺陷**完全没有出现在任何报告里**，它们同样计入那 12 条红检查点。

1. **暗色模式失效**：点顶栏那个太阳/月亮切换按钮之后，界面完全不变暗。看起来偏好是被记住了（再点一次也能切回来），可页面始终是亮色。
2. **侧边栏只能收不能放**：左上角那个折叠按钮，第一次点能把侧栏收成窄条，之后再点就没有任何反应，再也展不开。
3. **顶栏不吸顶了**：页面往下滚的时候，顶栏跟着内容一起滚出视野，不再固定在顶部。
4. **最近订单表格的状态配色反了**：「Pending（待处理）」的订单显示成红色，而「Canceled（已取消）」的显示成琥珀色，两个状态的配色像是被互换了；「Delivered（已送达）」的绿色是对的。
5. **首页 KPI 卡片的两个数字互换了**：「Customers」卡片与「Orders」卡片各自显示的是对方的数字（两张卡片上的涨跌幅小徽章仍在自己原来的卡片上，没有跟着换）。
6. **通知铃铛的未读小圆点永远不灭**：点开通知面板、看完之后再关掉，那颗橙色小圆点依然亮着。
7. **浏览器标签页标题慢一拍**：进入新页面之后，标签页标题显示的还是上一个页面的名字；刚打开站点时，标题里甚至会出现一个明显不该出现的占位字样。
8. **（请判断是否真的是缺陷）** 顶栏搜索框输入内容后没有任何反应：既不过滤列表也不跳转，按回车也一样。
9. **（请判断是否真的是缺陷）** 侧栏底部那张推广卡片里的 Purchase Plan 按钮会跳到站外的定价页，而且是在新标签页打开。

## 4 · 未报告的缺陷（线索）

除上面的报告外，还有若干缺陷**没有任何报告**。可观测的线索包括：

- 某些「当前项」少了应有的高亮色——问题不一定在组件里，也可能在**样式/设计令牌层**（界面上看就是元素在、但颜色不对或干脆没有渲染出来）；
- 导航分组的展开逻辑有问题：进入某个页面时，**当前页所在的那一组没有自动展开出子项**；
- 主内容区与侧栏之间的**水平偏移**在某些状态下对不上（内容被侧栏压住或留出大片空白）；
- 某个占比图形的**条形长度与它旁边的百分比文案不一致**；
- 另一张表格里的**状态徽章配色**与其状态语义不匹配。

这些同样计入 12 条红检查点，必须一并修复。

## 5 · 修复纪律

- **只做最小修复**：把被改坏的逻辑/样式恢复成模板本来的行为。不要重构，不要改依赖版本，不要新增依赖。
- 不要修改构建脚本、构建配置、端口或伺服方式；**不要关闭类型检查**（构建里带类型检查，类型层出错会让整条验收变成基础设施错误而不是行为红）。
- 源码里那一处挂在 `window` 上的验证桥（验证方注入，用于判断应用是否启动完成）请**原样保留**，不要删除、不要改名。
- **不要**把 history 路由改成 hash 路由，哪怕那样"看起来也能工作"。
- **不要**为了让某条检查点变绿而写死常量、加特例分支、按检查点名字做条件判断，或把断言目标元素整个移除。
- 不要手改 `dist` 里的构建产物；验收前会从源码重新构建。
