# 我们那套后台管理模板，最近好几处不对劲

我们内部用的是一套开源的后台／仪表盘模板（Vue 3 + Bootstrap Vue Next 那一套，版本号
2.3.0），既当管理后台的骨架用，也当组件演示册用。构建是 `npm run build`（它先跑一遍
TypeScript 类型检查，再打包），产物落在 `dist/`，伺服的也是这个目录，所以改了源码必须
重新构建才看得见。

界面大致是这样：最左边是一竖排可折叠的侧栏菜单，按 Dashboard／Elements／Components／
Forms／Tables／Pages 这样分组，点组头展开子项，当前所在的那一行会高亮、它上面那个组头
也会带一层「父项高亮」；侧栏左上角有个折叠钮，折叠以后菜单只剩图标，把鼠标移上去会临时
弹出一层浮菜单。顶部页头有页面标题、一个点开的搜索框、几个下拉，以及窄屏下才用得上的
两个开关（一个汉堡钮、一个菜单钮）。首页是一排指标卡（带涨跌百分比、箭头和颜色）加几张
图表卡；另外还有若干演示页：一个增强版的数据看板、手风琴、提示与气泡、分页、以及一张
可搜索的常规表格。

**离线约定**：这个包在浏览器里跑，页面不许向外部网络要任何东西，跨域请求数必须是 0。
种子原本在文档头部挂了一条外部字体链接，随包附带的适配把它摘掉了，所以字体回落到系统
字体；演示页里的地图瓦片与几张占位图本来指向外部图源，离线态取不到，因此是灰的／空白
的。这三件事都是预期之内的，别去替它们造数据、补外链，也别当成缺陷去修。

**先把话说在前面**：下面这些只是我们几个人平时用得到的部分，**并非所有缺陷都有报告
提及**。有些毛病我们可能压根没注意到，或者不知道该怎么形容，甚至根本不知道那是个毛
病。所以请你们自己把整套东西从里到外过一遍，别只盯着我列出来的这几条改；修别的问
题时弄坏的行为，同样会算在你们头上。

## 我们确实碰到的问题

1. 侧栏不再标出「你现在在哪一页」了。不管是从地址栏直接进一个内页（比如 Elements 组
   里的 Cards），还是在站内点着走，当前页对应的那一行都不高亮，它上面那个组头也没有
   父项高亮的样子。整份菜单看着像全都是没选中的状态。

2. 从地址栏直接进内页时，侧栏里对应的那一组子菜单不会自动展开，得自己再点一下组头才
   看得到当前页那一行；站内点着走的时候倒是会展开。以前不管怎么进，那一组都是自动张
   开的。手动点组头开合本身一直是好的。

3. 首页那排指标卡里，下跌的指标写成「-54.1%」这样带负号的，可它右边已经有一个向下的
   红箭头了，等于把方向写了两遍，看着像是数据出错。上涨的那几张卡没这个毛病。以前下
   跌的卡写的是「54.1%」，方向完全交给箭头和颜色表达。

4. 组件演示里的手风琴坏得很别扭：点一个**关着**的面板，它打不开；点那个**已经开着**
   的，又像是没反应（其实是被关掉了）。同一组里「点开一个、收起其它」的原意我们是要
   保留的，现在这两半都不对。同一页下面那组常见问答的开合是另一套逻辑，那个是好的。

5. 分页那张卡：把「每页条数」的下拉从 5 改成 10，再翻到最后一页（第 3 页），底下那句
   统计就写出了超过总条数的范围——"Showing 21 to 30 of 25 entries"，可表格里明明只
   有 5 行，右边也写着 Total 25 items。以前那句统计的结束序号最多到总条数为止。每页
   条数还是 5、只翻页的时候一切正常。

6. 常规表格那张卡的搜索框：输小写关键字（比如 engineering）一行都搜不出来，把首字母
   改成大写（Engineering）就正常了。以前大小写都能搜到同样的行。

7. 增强版数据看板右上角 Day／Week／Month／Year 四个按钮，高亮反了：当前选中的那个是
   描边的，另外三个反而是实心绿的；点 Week 之后还是一样反。以前选中的那个才是实心的。

## 有几处看着别扭，但我们确认过是正常的，别去「修」

- 增强版数据看板里那些「上涨＝绿色上箭头、下跌＝红色下箭头」的配对，还有首页指标卡的
  箭头与颜色，我们逐张核对过，都是模板本来的样子，别去把它们翻过来、也别改配色。上面
  第 3 条说的只是那个百分比数字自己多带了个负号，跟箭头和颜色无关。
- 地图演示页的瓦片是灰的、有几张图是空白占位、字体也不是设计稿里那款——这是上面那条
  离线约定的正常结果，别去补图、补字体、补外部地址，也别把这些块删掉或者藏起来。

## 修的时候请注意

- 跨域请求数必须保持 0；也不要在页面里留任何跨次运行的全局残留（本地存储、地址栏、挂
  在窗口上的变量都算）。种子里那几个本来就会记住「侧栏是否折叠」「主题」「通知设置」
  的地方，行为保持原样就好，别新加持久化。
- 侧栏这三件事各自独立：折叠／展开、鼠标移上去临时弹出浮菜单、当前页高亮。别为了让其
  中一条报告闭环把另外两条关掉或者改弱，也别去改菜单数据本身（增删条目、改标题、改指
  向都算）。窄屏那两个开关各管各的，别把它们的作用对调。
- 手风琴要保持「点开一个、收起其它」的原意，别把开合逻辑整个去掉，也别让关着的面板永
  远打不开；常见问答那一组的独立开合逻辑不要动。
- 分页那张卡：底部那句统计要和表格里真正渲染出来的行对得上，别把这句文本硬写死，也别
  把翻页能力或「每页条数」下拉摘掉；改每页条数时页码会自己回到第 1 页，那是分页组件本
  来的行为，别去替它加一层、也别把它关掉。那张卡以外的其它分页演示本来样式就各不相同，
  不用去统一它们。
- 表格搜索要保持大小写不敏感的原意，别把过滤整个关掉（一律返回全量），也别只让某几个
  列可搜；表格里的状态徽章配色是好的，不要动。
- 涨跌百分比与箭头／颜色的分工要保持原样：数值不带符号，方向由箭头和颜色表达。
- 浏览器标签页上的那句标题、页头那一大一小两行标题，都按模板本来的分工渲染，别为了某
  条报告去改文案。
- 修完以后 `npm run build` 必须还能过（它先跑一遍类型检查），产物还得照常落在 `dist/`。
