# 我们那套自己玩的网页版太空经营游戏，数值到处不对

我们内部维护的是一套 Vue 3 + TypeScript 的浏览器端太空资源经营游戏：一个星球，几种资源（金属、晶体、氘，外加暗物质），左边一竖排导航（总览、建筑、研究、造船厂、军备、舰队、军官、星系……），主区域是卡片和表格。玩法就是攒资源、升建筑、研科技、建军备，右上角和侧栏会按你造过的东西累计积分。存档存在浏览器本地，打开网页就能接着玩。最近这一版升完以后，好几处数值明显不对。我们组没人会写前端，只能把眼睛看到的现象照实说出来，麻烦你们从头查一遍、修一修。

**先把话说在前面**：下面这些只是我们几个人平时看得到、说得清的部分，**并非所有缺陷都有报告提及**。有些毛病我们可能压根没注意到，或者不知道该怎么形容，甚至根本不知道那是个毛病；还有的毛病被别的毛病盖住了——得先把外面那一层修好，里面那层才看得见读数。所以请你们自己把整套数值逻辑从里到外过一遍，别只盯着我列出来的这几条改；修别的问题时弄坏的行为，同样会算在你们头上。

## 我们确实碰到的问题

1. 总览页那张资源表，「每小时产量」一栏里金属、晶体、氘三行全变成了 `+0`（晶体那行以前是 `+20.25K`）；可同一张表里能量那一行明明是正的，产出 `+402`、消耗 `-338`，电站也没坏。以前这三行都是有正数的。

2. 建筑那边的倒计时全偏短。我们核了机器人工厂升 3 级这一项：按公式手算应该是 `00:00:32`，页面上只显示 `00:00:22` 就造完了；别的建筑也一样偏短，纳米工厂等级越高、差得越明显。

3. 研究那边正相反，时间变长了：能源科技升 4 级以前是 `00:30:20`，现在是 `00:40:27`，平白多等十分钟。

4. 军官页里我们的暗物质专家明明还在有效期内（还剩三天，卡片上也没说过期），可每次结算只给 `+150` 暗物质，以前是 `+187`。

5. 侧栏那个「总积分」现在只有 `408`，我们自己按造过的东西手算是两千出头（`2.23K`）；其它页面显示的积分倒没这个毛病。

6. 造船厂页那个「舰队占用仓储」的数字大得离谱：我们一共才 5 架轻型战机、2 艘小型运输船、3 个探测器，它显示 `375`；右边那个上限（`4.00K`）是对的，下面舰队列表里的船数也是对的。

7. 我们存档里设的是深色主题，可每次打开页面都是亮的，得手动点一下切换按钮才变暗；一刷新又变回亮的，怎么都记不住。

## 另外两件我们拿不准算不算毛病的事

（这两条有可能是我们自己想多了、本来就是设计如此。请你们先判断是不是真毛病，再决定要不要动；如果本来就是正常行为，把它「修好」反而会把别的东西弄坏。）

8. 界面语言我们设的是英文，页面上其它文字（导航、资源名、按钮）确实都是英文，只有星球名字一直显示成中文「母星」。是不是语言包漏翻了这一条、还是我们存档坏了？要不要把它改成英文？

9. 三种资源的库存数字一直卡在 `80.00K` / `40.00K` / `20.00K` 一动不动，和上面显示的「每小时产量」对不上（产量是正数，库存却不涨）。是不是产出来的资源没进账、被谁吞了？要不要让它接着往上涨？

## 环境说明

- 这个应用跑起来**不需要外网，也不需要任何后台服务**：存档、星系数据、成本表这些都是随包带的本地数据。我们这边是拔了网线试的，页面自己一个外部请求都没发出去，也没有弹新窗口、没有跳登录。
- 浏览器窗口是按 **1280×900** 试的，桌面尺寸；换个宽度有些地方会换成另一套排版，现象可能不一样。
- 存档是**固定的一份**（一个星球，坐标 `1:1:8`，固定的建筑／科技／军备等级、固定的资源数和暗物质数），星系里除了我们这颗只有固定的一颗哨兵星，所以每个数字都是可复现的，不会每次打开都变。
- 每一项检查都是从一个**全新的页面**重新开始的：上一屏排进队列的建筑／研究／军备、点过的切换按钮、改过的设置都不会带到下一屏，也不会有上一次跑剩下的本地存储。
- 页面里挂了一小段给自动化验收用的**只读探针**（记录页面有没有起来、有没有往外发请求、有没有报错，以及存档里的坐标、队列这些只读事实），请**不要删掉它、不要改名、也不要让它去读写业务状态**；我们看不出你们动了它，但验收会。
- 上面全是使用者视角的原话。我们不会去翻代码，也没本事告诉你们原因在哪儿、该改哪个文件；哪几条是真毛病、哪几条本来就是设计如此（第 8、9 条就有可能是我们自己想多了），得你们自己判断。
- 页面上的数字是按固定格式缩写显示的（`20.25K`、`1.6K`、`408` 这种），倒计时是 `时:分:秒`。你们核对时请**以数值本身为准**，不要以缩写位数、千分位写法或者秒数末尾的零为准；涉及「还剩几天过期」「排了几项」这类判断，也请用相对说法，别写死具体日期。
- 改完以后整套东西还得能**照常打包出来**，别为了绕过现象把功能整块删掉、把卡片去掉、把队列长度写死、或者把某个数值直接硬编码成我们报的那个数——那样我们会当成新毛病算在你们头上。
