# 「H5 低代码编辑器」内网部署：使用者反馈汇总（请修复）

我们把这个可视化的 H5 页面搭建工具搬到内网，给运营同事自己拖组件、拼活动页用。上线两周，收到一批
反馈。下面这些都是他们在浏览器里**实际看到的现象**，我按收到的先后原样转述，没有替他们做任何技术
判断，也没有去翻代码核对；其中混着两条我们自己也拿不准算不算毛病的抱怨，请自行甄别。

> ⚠️ 先说一句要紧的：这份反馈**并不完整**，并非所有缺陷都有报告提及。有些毛病没人反馈，
> 但验收的时候照样会检查。请你自己把整个编辑器从头到尾走一遍做个体检——左栏、画布、右栏、
> 顶栏工具条都点一遍，别只照着下面这七条改。

## 一、明确报上来的七条

1. 左边那一竖排页签的顺序反了。以前从上到下是「页面 / 数据源 / 基本组件 / 容器组件 / 业务组件」，
   现在变成「业务组件」排在最上面；而且一进页面默认展开的就是它——那一栏在我们这儿是空的，
   每次都得先自己点回「页面」或者「基本组件」才能开始干活。

2. 左栏「页面」里的页面树，节点名字全变成了路径。原来显示「首页（/）」「关于（/p2）」，
   现在显示成「/（/）」「/p2（/p2）」，一眼看不出哪个是哪个页面了。

3. 选中画布里的表单字段类组件（比如那个「表单项类型 - 输入框」）时，右边属性面板只剩
   「属性 / 动画 / 事件 / 页面设置」四页，「规则」那一页不见了；只有选「表单容器」的时候才有
   「规则」。以前选任何表单类的组件都是有的。

4. 右边切到「页面设置」，在「背景图片」里填了图片地址（或者用「背景颜色」选了个颜色），
   输入框里的值确实存住了，可中间画布的背景**从来不变**，永远是白的。

5. 选中画布上的文本组件，右边「组件对齐方式」里点「居中」，按钮自己变成选中态了，
   但画布里的文字还是靠左。「左对齐」「右对齐」两个都正常，只有「居中」没效果。

6. 左栏「数据源」里的数据模型列表顺序反了。原来是「用户信息」在上、「订单信息」在下，
   现在「订单信息」跑到最前面去了。

7. 画布上所有文本组件显示的都是「默认文本」四个字。明明右边「显示文本」里填的是真实文案，
   也存住了，画布上就是不改，全变成「默认文本」。

## 二、我们也拿不准算不算毛病的两条

A. 顶栏工具条上的「撤销」「重做」「清空页面」「复制页面」四个按钮，点了都只弹一句「敬请期待！」，
   什么都不做。是坏了，还是本来就没做完？要不要接上？

B. 工具条最右边那个「反馈」，还有右上角悬浮出来的那两个代码仓库小图标，点了都跳到公网上去。
   我们内网机器上点了就是打不开。能不能把它们去掉，让界面干净点？

## 三、验收口径

- 第一部分 1~7 条描述的现象，修完之后都不应再出现。
- A、B 两条**如果本来就是设计如此**（上游就没接完／本来就是外链），**请保持原样**，不要为了
  「看起来更干净」去删按钮、删图标、改文案；验收会反过来检查这两处的既有行为有没有被破坏。
- 不要去改构建产物目录里的东西，也不要靠给页面加测试专用标记、加特判分支、写死返回值来让检查通过。
- 界面上的文字、菜单项、页签条目、组件清单、默认值这些都应保持原样（除了上面 1~7 明确要求修的）。
- 工具整体仍然是纯前端、离线可用，不要引入任何新的外部请求。
