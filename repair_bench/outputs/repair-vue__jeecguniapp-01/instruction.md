# 我们那套 JeecgBoot 移动端 H5，最近好几处不对劲

我们内部用的是 JeecgBoot 配套的那个移动端（uni-app 一套代码多端出），我们只跑它的 H5
那一面：Vue 3 + TypeScript + Vite，构建命令是 `pnpm run build`（就是 uni 的生产构建），
H5 产物落在 `dist/build/h5/`，伺服的就是这个目录，所以改了源码必须重新构建才看得见效果。

界面大致是这样：底下三个页签——消息、协作、个人。消息页上面还有两个子页签，一个是
「消息」（会话列表，每行显示名字、一行状态或类型文案、还有时间），一个是「通讯录」；
通讯录最上面是三个固定入口（联系人、我的群组、更多功能），再往下才是我们几个租户。
协作首页有两栏服务宫格，「常用服务」和「其他服务」，点哪一项就跳到对应页面，右下角
还有一个「更多」。个人页有组织、扫码、定位、设置、退出五个入口。除此之外还有一批示例
页（索引条搜索、树、表单、多选、仪表盘示例、组件示例长廊），我们拿它们当内部培训材料，
也算产品的一部分，坏了一样要修。

后端不在这个环境里。它本来要连我们那台 JeecgBoot 服务器——登录、用户信息、公告列表、
租户列表都走接口。在这里，这些接口由随包附带的一个本地替身应答，返回的是固定数据，
登录态也是它预先塞好的，所以一打开就是已登录的样子。整套东西在纯浏览器里能正常启动、
正常操作；页面自己不会去访问外网，也不该访问。

**先把话说在前面**：下面这些只是我们几个人平时用得到的部分，**并非所有缺陷都有报告
提及**。有些毛病我们可能压根没注意到，或者不知道该怎么形容，甚至根本不知道那是个
毛病。所以请你们自己把整套东西从里到外过一遍，别只盯着我列出来的这几条改；修别的
问题时弄坏的行为，同样会算在你们头上。

## 我们确实碰到的问题

1. 消息页两个子页签点开都是空的。页签本身还在（「消息」「通讯录」两个都在，也能点
   着切），可下面一片空白：会话一条都没有，通讯录那一栏也是空的。以前打开就能看见九条
   会话记录，置顶的那条在最上面。这条最要命，我们现在整个消息页等于废了。

2. 索引条那个示例页，一搜就全空了。在搜索框里打一个「州」字，本来应该把名字里含
   「州」的城市筛出来（广州、郑州、杭州那些），现在整页什么都不剩，左边那一排 A 到 H
   的索引字母也跟着整个消失了。把搜索词清空以后倒是能恢复成原样。

3. 登录态过期或者被清掉之后，页面照样能进去。我们把本地存的登录信息里的令牌清空
   （就是模拟过期那一下），再去打开「个人中心」这类需要登录的页面，它居然直接进去了，
   没有弹回登录页。以前是必弹的，白名单里那几个页面才不弹。

4. 首页点哪个服务都跳到组件示例长廊。常用服务那一栏里点「通知公告」，本来应该进公告
   列表，结果落到「组件示例」那个长廊页去了；换别的入口点，也一样往那儿跳。

5. 「其他服务」那一栏跟「常用服务」长得一模一样。以前其他服务只有五项——新闻中心、
   会议、任务中心、合同、更多；现在两栏都是十三项，逐项一字不差。「更多」那个页面里
   的四项倒还是对的。

6. 树示例里点「全选」，一个都没勾上。八个操作按钮都在、也点得动，点完「全选」之后
   第一棵树的复选框一个也没打上勾，看着像什么都没发生。（「取消全选」我们没去点，
   所以不知道它现在是什么行为。）

7. 表单示例不填姓名也能过校验。什么都不填直接点提交，性别和密码那两条必填提示都还
   在，唯独姓名那条不报了，等于姓名的必填被摘掉了。

🔴 提醒一句：第 1 条（两个子页签都是空的）很可能盖住了别的东西——列表压根没渲染出来，
列表里面的毛病自然谁都看不见。等第 1 条修好、数据回来了，请把消息页和通讯录页从头到尾
再看一遍：很可能还有没写在这份报告里的问题，而且一条报告未必只对应一处改动。

## 另外两条我们自己想明白了，不用改

8. 「仪表盘示例」那个页面打开是空的，中间只有一行「暂无内容」。一开始我们以为跟第 1 条
   是一回事，后来想明白了：那个页面要靠后端返回的模板配置来画卡片，我们从来没给它配过
   任何模板，空着才是它本来的样子，那行提示就是产品自带的空状态文案，不是坏掉了。

9. 「我的消息」（公告列表）那个页面，顶上写着英文 Pull down to refresh，底下写着
   No data，看着像国际化漏翻了。这两串文案来自随包带进来的那个第三方下拉刷新组件自带的
   默认语言包，我们从来没配过它的多语言；那个目录是第三方代码，按我们的规矩不动它。
   列表为空也是真的——这个环境里就没有公告数据。

## 请你们照着修的时候，别动这些

上面第 8 条和第 9 条我们后来自己想明白了，那两处本来就是产品该有的样子：仪表盘示例在
没有任何模板配置的时候显示空状态文案，是它一直以来的正常形态；第三方组件的默认英文
文案也不是这一版才出现的。这两条不用改，也不该改——如果你们为了让报告「闭环」而往
仪表盘里塞示例卡片、删掉空状态分支，或者把那两串英文硬编码成中文，那反而把好的行为
改坏了。

同样地，下面这些请保持原样：

- 那个应答接口的本地替身，以及随包附带的那一套只读观测点，是这个环境的一部分：一个字
  都不许改、不许删，也不许自己再造一个替身去顶掉它；
- 第三方目录不在改动范围内：随包带进来的那些组件目录（第 9 条那个下拉刷新组件就在
  `src/uni_modules/` 底下）、还有依赖目录，都不要动；
- 页面不许向外网要任何东西；连不上真后端是预期之内的，别去给它造假数据，也别把报错
  藏起来；
- 登录态那一份持久化该走应用自己的存储通道，不要改成另外往浏览器本地存储里塞东西，
  也不要留下任何跨次运行的全局残留、全局开关或者硬编码的特例分支来让某一条报告闭环；
- 示例页里那些种子数据现在是对的（会话九条、树的第一棵初始勾着两个节点、索引条 A 到 H
  八组一共一百多个城市），别顺手把它们改了来让读数好看；
- 会话列表、通讯录、宫格那些地方的正常行为（页签能切、宫格能点、下拉能刷新）现在都是
  好的，别为了修某一条把它们弄坏。

修完以后 `pnpm run build` 必须还能过，H5 产物还得照常落在 `dist/build/h5/`，我们判分
就是起这个目录、在浏览器里把它当普通 H5 应用点一遍。
