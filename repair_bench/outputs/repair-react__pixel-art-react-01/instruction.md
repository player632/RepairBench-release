# 修复请求：像素画动画编辑器

我们内部在用的这个像素画 + 动画小编辑器（纯前端、离线运行，作品都存在浏览器本地存储里）最近问题不少，麻烦帮忙排查修复。以下是收集到的反馈：

1. 画笔不太对劲：鼠标在画布格子上**单点**一下，格子不上色；但按住鼠标拖动，经过的格子又能画上去（起笔那格还是不上色）。以前单点一下是立刻上色的。
2. 做动画的时候：只有两帧的话，预览区按播放键动画死活不动；帧数多加几个倒是能播。我记得以前两帧就能播的。
3. 就算动画能播，节奏也不对：我明明把 Duration 设成了 2，整个动画一轮跑完明显不到 2 秒，感觉快了一倍。
4. 右上预览区的画面变小了：像素尺寸只有以前的一半；点缩放按钮，本该切换大小，现在方向整个反了。
5. 保存这条链路有问题：点 SAVE 之后刷新页面，回来的不是我刚保存的那幅画——要么变回存档里最开头那个示例，要么干脆是空白画布。总之保存之后"当前项目"就指不对地方。
6. 右上角的保存提示不消失了："Drawing saved" 以前两三秒就自己淡出，现在一直挂着不动，只有刷新页面才没。
7. 画布上的坐标提示横向差了一个：鼠标悬停某个格子时，显示的 X 坐标比格子实际列号小 1（Y 是准的）。比如悬停第 6 列第 2 行的格子，显示成 "5, 2"。

另外有位同事反馈：第一次打开网站时画布是空的，可本地存储里明明躺着一个示例项目（一只猫），他怀疑"首次加载"坏了。我印象里这工具一直这样——第一次进来就是空白格子，之后才会恢复上次的内容。帮我确认一下这个行为到底是不是毛病；如果本来就是设计如此，就不要动它。

Not every defect is necessarily mentioned in the reports. Behaviors you break while fixing other things still count against you.

要求：
- 应用必须保持纯前端离线运行，不要引入任何对外网络请求。
- 不要破坏本地存储里已有数据的结构和已保存的作品；保存/读取/删除的既有格式要兼容。
- 不要改动界面的类名、结构和配色，只修行为问题。

## 验证方式说明

作答期间请不要自行运行项目的构建、开发服务器或测试来验证改动；会有单独的验证器重新构建并操作应用。请把精力放在阅读代码和定位根因上。
