# 修复任务：microtube（SolidJS 写的 YouTube 播放器前端）

你面对的是 **microtube** 的源码：一个用 SolidJS + TypeScript 写的 YouTube 播放器单页应用，
vite 打包，另挂了一个 PWA 插件（会生成 service worker）。仓库不大（93 个应用文件、6291 行，
其中 52 个 .tsx / 33 个 .ts），`package.json` 就在**仓库根目录**，所有 npm 命令都在根目录跑。
它自己不带货架后端：数据一路走 YouTube Data API v3 那一套接口（播放列表、播放列表条目、
视频、频道、订阅、搜索），另一路走一个实时数据库做状态同步与登录态。路由有这几张：

- **首页**（`/`）：播放列表卡片列表，每张卡有缩略图、标题、以及一句「有几条视频」的计数徽章。
  卡片上右键会弹出菜单（Launch、Share 等）。
- **播放列表详情**（`/playlist/:id`）：这个列表里的条目，每行左边一个序号，行内是缩略图
  （右下角带时长角标）、标题、频道名（可点，跳频道页）、发布日期；行尾一个菜单按钮，
  右键整行也会弹菜单（Save to playlist、Share 等）。列表是虚拟滚动的，滚到底会再拉一批。
- **频道页**（`/channel/:id`，下面还有 `/videos`、`/playlists`、`/about` 三个页签）：频道头图与名称，
  下面按页签分别列视频、列播放列表；About 页签是频道简介正文——简介里的裸网址和邮箱地址
  会被自动转成可点的链接（网址开新窗口，邮箱走 mailto）。
- **搜索**（`/search`）、**订阅**（`/subscriptions`）、**登录**（`/login`）、**回调**（`/callback`）。
- 其它任何路径落到一张 404 页，正文写着 “Content not found.”。

播放器本身常驻在页面底部：**一条播放器横条**（当前条目的标题、当前时间／总时长两个读数、
上一个／播放暂停／下一个、信息、队列、屏幕、收藏、展开等一串图标按钮）；点队列按钮从下方
滑出**队列面板**，面板头部一句写着队列条数的标题，头部右侧是导入、清空、关闭三个按钮，
面板体是队列行（每行左边是序号、当前播放的那行换成一个均衡器动画图标），行上右键弹菜单
（Save to playlist、Share、Remove from queue）。导入是一个文本框，一次粘一批 YouTube 链接
或者裸视频 id，一行一个。做过某些操作之后右下角会弹一条提示，几秒后自己消失。应用状态
（登录态、队列、当前条目等）会写进浏览器本地存储，下次打开时还原。

工程就在当前工作区里，完全离线。依赖已经装好；在仓库根目录跑 `npm run build` 会把产物打到
`dist/`（`package.json` 的 build 脚本就是 `vite build`，没有单独的类型检查步骤），判分链路就是
伺服 `dist/` 之后用真实浏览器驱动界面。**没有任何网络访问**：判分环境用一份确定性的离线桩
顶替 YouTube Data API 与那个实时数据库，桩里的数据是写死的夹具（3 张播放列表——其中一张
刻意不带条目数字段、一张带 3、一张带 1；那张不带字段的列表里有 4 条条目，时长分别是
PT1H2M3S／PT10M15S／PT1H3S／PT45S；1 个频道；1 条一开始就在队列里的视频），所以你看到的
每个读数都是可复现的，不会因为跑的时刻不同而变。

QA 收集了一批用户报告，另外附了两条内部走查时记下的疑问。下面基本按原话照录——带着他们
自己的操作步骤、噪音和猜测。把它们当起点，不要当诊断结论：

- 大部分报告描述的是真实、可复现的缺陷，每一枚都有自己的根因；根因所在的文件未必是症状
  表现出来的那个地方，同一个症状也可能有好几个候选解释。
- 至少有一条记录描述的其实是**本来就该这样**的行为。动手改之前先自己复现、先鉴别：把不是
  缺陷的东西「修」掉，一样算你弄坏了行为。
- **并非所有缺陷都有报告提及**，报告里没有全部列出。没被提到的缺陷同样在判分范围内；你在
  修别的问题时顺手弄坏的行为，也一样算你的失分。

报告与走查记录如下，顺序没有意义：

1. 「播放列表里每条视频的时长角标都差一点：明明是一小时两分三秒的片子，角标读成 01:02:05。我一开始以为是自己看错了，可对了好几遍，秒那一位总是多两秒；小时和分钟倒是对的。同一批视频我在别的地方看到的时长又好像没问题——说不准，我也没拿秒表去掐。」

2. 「播放列表里的时长整整多了一个量级：一条一小时的视频，角标读成 02:02:03，小时那一位凭空翻了一倍。分钟和秒看着还是老样子，所以第一反应是『这片子是不是有两个小时的版本』，可点进去播的还是同一条。」

3. 「播放器下面和队列里的时间全掉前导零了：本来齐刷刷的 01:02:03，现在写成 1:2:3，长短不齐、看着像没对齐的表格。数字本身我倒没算出错，就是排版看着特别廉价，角标宽度还跟着一起抖。」

4. 「从『导入视频』粘一批链接进队列，结果队列里只多了一条，标题还不是我要的那几条。我把三行链接逐字检查过，格式没写错；换成直接粘裸 id（不带域名那种）反倒是对的。」

5. 「不到一分钟的视频，时长角标从『00:45』变成了『00:00:45』，凭空多出一截全零的小时位。数字加起来还是对的，可整列角标宽度都不一样了，短视频看着像三个字段、长视频也是三个字段，分不清谁是谁。」

6. 「播放列表卡片上写着『1 video』，可点进去是空的，一条都没有。我以为是列表没加载出来，退出重进还是 1；旁边那几个明明有内容的卡片数字倒是对的。」

7. 「队列里明明选中了一条视频、高亮也在那一条上，可播放器横条上的标题写的是『No video.』，时长也变成 --:--。我点了别的条目，高亮会跟着动，标题却一直是那三个字。」

8. 「走查的时候看到一处像是漏写了一半的地方。有个负责『把外部脚本插进页面』的异步函数，整个函数体都包在『这个脚本还没被插过』那个判断里面，没有 else 分支——也就是说脚本已经插过的时候，它什么返回值都不给，等于返回 undefined。可它的签名写着 async，调用它那一行写的是 await。看着像是要等一个永远不会来的 Promise，是不是该补一个 else 返回一个已解决的 Promise？想先问清楚这是有意为之还是漏了，我们下游有人照它的类型签名写过东西，怕炸。」

9. 「播放列表详情页每一行左边有个序号，从 1 开始数：1、2、3、4。可首页那三张播放列表卡片**没有**这一列。看着像是首页那半边没做完——是不是应该也补上序号、两边一致？我们做无障碍走查的时候，读屏在详情页会念出『1、2、3、4』，在首页什么都不念，体验不一致。想确认一下是有意为之还是漏了。」
