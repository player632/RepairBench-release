# 修复任务 — ngx-widget-grid（Angular 可拖拽 / 可缩放的仪表盘网格）

你拿到的是 **ngx-widget-grid** 这个仓库的一份工作副本。它是一个 Angular 15 的组件库，
仓库里同时住着两样东西：库本身（一个仪表盘网格组件，卡片可以拖着走、可以拉角上的手柄改大小、
可以互相交换位置），以及一个演示应用，把库铺在页面上给你看。演示应用一共 3 页：
一页说明，两页网格演示，两页网格用的是同一套组件，区别只在于网格尺寸是跟着容器走还是写死的。

这个应用**不跟任何服务端说话**：没有接口、没有数据库、没有长连接、也没有任何本地存档。
你在页面上看到的一切，全部来自组件在运行时算出来的位置和样式。它现在**坏了**：
有人在这份代码里留下了若干处缺陷，用户一眼就能看出来，但程序不会崩、控制台也不会报错 ——
页面照常打开，卡片照常画出来，只是**位置、蓝色落点预览框、以及松手之后的结果**不对。

## 交付态是怎么跑起来的（作答前请先读）

- 构建就是仓库自带的那一条脚本，一步到位。
- 依赖是离线可恢复的，恢复完之后整个构建不需要联网。
- 🔴 **站点根不是 `/`。** 这个应用的构建命令自带一个 base-href，产物里所有资源都按
  `/ngx-widget-grid/` 这个前缀解析，所以构建产物要用静态服务器挂在站点根上、然后访问：

      http://127.0.0.1:12043/ngx-widget-grid/

  直接访问 `http://127.0.0.1:12043/` 会拿到一个资源全部 404 的空壳，那不是应用坏了，是地址写错了。
- 页面之间用的是**哈希路由**（路由模块 `src/app/app.module.routing.ts:35` 里 `useHash` 是打开的），
  所以地址形如 `http://127.0.0.1:12043/ngx-widget-grid/#/about`、`http://127.0.0.1:12043/ngx-widget-grid/#/basic`、`http://127.0.0.1:12043/ngx-widget-grid/#/fixedDimension`；直接打开 `http://127.0.0.1:12043/ngx-widget-grid/` 会被重定向到 `#/about` 那一页。
  其中 `#/basic` 与 `#/fixedDimension` 才是真正的网格演示页，
  本任务的验收用例就跑在这两个地址上（实测这个应用的导航目标只有：`#/basic`、`/ngx-widget-grid/（无 hash，落到默认页）`）。
  🔴 要换页面**请直接改地址栏里的 hash**，不要去点页面上的导航链接 ——
  点导航走的是同一条路由，但它会把「页面切换」和「用户手势」混在一起，你自己复现问题时不容易分清。

## 你要做的事

把这些缺陷找出来并修好，让这个网格回到它本该有的行为。修完之后，这份代码必须**照常构建成功**，
并且下面这些用户报告里描述的现象必须消失。

🔴 **并非所有缺陷都有报告提及。** 下面这些用户报告只覆盖了一部分问题；其余的缺陷没有任何报告，
需要你自己看出来。同时，你在修某一个问题时**顺手弄坏的其他行为也会被记账** ——
这个网格原本正常的功能（拖动、缩放、交换、加卡片、网格线、预览框），修完之后必须依然正常。

## 判分方式

判分是自动的：把你修好的代码构建出来，用真实浏览器打开，然后跑一批**行为验收用例**。
每个用例只在页面上做几个真实手势（悬停、按下、拖动、松手、点按钮、勾复选框），
读几个数值或几段可见的样式，然后和预期值比较。用例分两组：

- **必修组**（12 项）：当前一定是红的，修对了才会变绿。上面这些用户报告各自对应其中至少一项，
  剩下的那些对应的是**没有报告**的缺陷。
- **回归组**（26 项）：当前一定是绿的，修完之后必须**依然是绿的**。这一组里包含上面
  2 条「非缺陷报告」的守卫：把正常设计改掉会让它们变红。

得分是**全有或全无**：必修组与回归组全部通过才算修好（退出码 0）；只要有一项不对就是 0 分（退出码 1）。
退出码 2 表示判分器自身出了基础设施问题（构建失败、产物缺失、服务起不来等），那不是你的答案在受评。

判分用的浏览器视口是 1280x720，语言 en-US，时区 UTC。请在这个视口下自证。

🔴 这个网格的行为**依赖真实的手势序列**：按下、移动、松手分别派在不同的目标上，
中间还有真实的等待。只读页面初始快照是看不出多数缺陷的，请在页面上真的把卡片拖一遍再判断。

## 硬规则

1. **不要给判分器做特例。** 不得读取或依赖任何环境变量、URL 查询串、UA 字符串来改变行为；
   不得在代码里写死任何用例的预期数值；不得因为「被测到了」而走另一条分支。
   所有验收用例读的都是这个网格对用户可见的行为，写死数值不会让任何一项变绿。
2. **不要新增测试钩子属性。** 不得往模板里加 `data-testid` / `data-test-id` / `data-cy` 一类的标记：
   判分不读它们，而它们会改变交付代码的形状。
3. **不要改动构建配方。** 构建命令、产物目录、依赖清单、以及仓库里那份路径映射配置，
   都要保持交付时的样子；你的修改必须能让原有构建命令照常成功。
4. **不要引入新的全局变量、新的网络请求、新的第三方依赖、新的本地存储读写。**
   这个应用现在完全不落任何状态（没有 localStorage / sessionStorage / cookie / indexedDB），
   保持它这样。
5. **不要绕过组件自己去改 DOM。** 判分读的是页面上真实渲染出来的位置与样式；
   直接往元素上写内联样式能骗过一两个用例，但会同时打红一批回归用例。
