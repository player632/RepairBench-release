# 我们那个 sing-box 图形前端，最近好几处不对劲

我们内部用的是 GUI.for.SingBox：给本地 sing-box 内核配的一套图形界面，本来是 Wails
桌面应用（外面一层 Go 壳子），我们平时只用它的前端那一半——Vue 3 + TypeScript，构建
是 `pnpm run build`（先做一遍类型检查，再打包），前端产物落在 `frontend/dist/`，伺服
的就是这个目录，所以改了源码必须重新构建才看得见。

界面大致是这样：左边一竖排导航——概览、配置文件、订阅、规则集、定时任务、插件、设置；
概览页上半是内核状态，下半是一排配置文件卡片，点哪张就把当前使用的配置切成哪张；
配置文件页有网格和列表两种视图（右上角能切），卡片可以拖动排序，页面上方有个「添加」
按钮，点开是一个七步向导，走完就新建一份配置；每张卡片上还有一个「更多」按钮，鼠标
移上去会弹出重命名、复制、删除那一组动作；设置页里能改主题、主色、语言、字体，还能
勾选哪些页面出现在左边导航里，改完应当自动存下来。

它本来要靠桌面壳子去读写配置文件、画系统托盘、开外部链接。我们在浏览器里用的时候，
这些能力由随包附带的一个本地替身顶着（它带一份虚拟的文件系统，读写都落在内存里），
所以整套东西在纯浏览器里能正常启动、正常操作。真正要去连本地内核的那一小部分（发
请求、开长连接）在浏览器里连不上，这一点我们都知道，算正常，别去给它造假数据；外部
链接也只在点击的时候交给壳子，页面自己不会去访问外网。

**先把话说在前面**：下面这些只是我们几个人平时用得到的部分，**并非所有缺陷都有报告
提及**。有些毛病我们可能压根没注意到，或者不知道该怎么形容，甚至根本不知道那是个
毛病。所以请你们自己把整套东西从里到外过一遍，别只盯着我列出来的这几条改；修别的
问题时弄坏的行为，同样会算在你们头上。

## 我们确实碰到的问题

1. 配置文件全都不见了。以前打开软件，概览页下面那排卡片、还有配置文件页里的卡片，
   就是我们攒的那几份配置，现在两处都是空的，一份都没有。奇怪的是订阅页和规则集页
   里那几条种子条目都还在，所以不像是整个数据目录读不出来，倒像是单单配置文件这一
   路没被加载进来。这条最要命，我们现在根本没法切换配置。

2. 左边导航里「设置」那一项不见了，剩下几项都还在。我们在地址栏里直接敲
   `#/settings` 还是能进设置页，页面本身也正常、内容也在，就是导航里没有那个入口，
   平时只能靠手敲地址进去。

3. 在设置里把语言切成简体中文，界面还是英文的。选完以后左边导航、页面标题、按钮
   全都没变，得把整个软件关掉重开才有可能变过来。以前是切完立刻就变的。

4. 设置改完存不住。我在设置里把语言改成简体中文，当时看着没生效（见上一条），想着
   算了先这样；结果关掉软件再打开，语言又回到英文了——好像我那一下根本没被记下来。
   改主题、改主色倒像是能存住，偏偏这类嵌套在里面的选项改了不落盘。

5. 用「添加」向导新建配置的时候，名字存不下来。向导能正常打开，七步一步不少，最后
   那个保存按钮也在、也能点，走完流程以后新卡片确实多出来了，可是标题是空的——我在
   第一步填的名字没被带进去。填的时候输入框里明明是有字的。

6. 概览页点卡片，高亮跑偏。以前点哪张哪张就变成选中的样子；现在我在第二张上点一下，
   亮起来的却是别的卡片，我点的那张反而没亮。切换当前配置这件事本身好像是成了的，
   就是那个「选中」的样子对不上。

7. 网格视图下，鼠标移到卡片上那个「更多」按钮，动作菜单不弹出来了。以前移上去停一下
   就会弹出重命名、复制、删除那一组；现在移上去等多久都没反应，菜单一次也没出现过。

🔴 提醒一句：第 1 条（配置文件全没了）很可能盖住了后面第 6、7 条——卡片都不在了，
自然也就看不到卡片上的毛病。第 6、7 条是我们在那之前记下来的，等第 1 条修好、卡片
回来了，请你们再复核一遍这两条是不是真的好了；很可能每一条都还得单独再修一处才算
数，别以为卡片回来了它们就自动跟着好了。

## 另外两条我们自己想明白了，不用改

8. 定时任务页和插件页打开都是空的，只有一行「列表为空」那样的提示。一开始我们以为
   跟第 1 条是一回事，后来想明白了：这两处我们确实一条都没建过，空着才是它本来的
   样子，那行提示就是产品自带的空状态文案，不是坏掉了。

9. 「添加」那个向导有七步，从名字一直问到路由、代理、DNS 之类，感觉有点啰嗦。是不是
   谁把流程改长了？能不能砍掉几步、让它两三步就建完？

## 请你们照着修的时候，别动这些

上面第 8 条和第 9 条我们后来自己想明白了，那两处本来就是产品该有的样子：定时任务和
插件两页在没有任何条目的时候显示空状态文案，是它一直以来的正常形态；新建配置的向导
一直就是七步，每一步问的都是这份配置真正要用到的东西。这两条不用改，也不该改——如果
你们为了让报告「闭环」而往定时任务或插件里塞示例条目、或者把向导砍成两三步，那反而
把好的行为改坏了。

同样地，下面这些请保持原样：

- 真正去连本地内核的那部分在浏览器里连不上是预期之内的，别去给它造假数据，也别把
  报错藏起来；
- 桌面宿主那几样能力（读写配置文件、系统托盘、外部链接）继续走随包附带的那个本地
  替身，页面依然不许向外部网络要任何东西；
- 设置里那些选项改完要落盘，走的应当是应用自己的存储通道，不要改成往浏览器本地存储
  里塞东西，也不要在页面里留任何跨次运行的全局残留；
- 卡片可以拖动排序，这个行为本身是好的，别为了让某条报告闭环而把拖拽关掉；
- 订阅页和规则集页那几条种子条目现在还在，那是正常的，别顺手把它们也「修」没了。

修完以后 `pnpm run build` 必须还能过（它带类型检查），前端产物还得照常落在
`frontend/dist/`。
