# 修复任务：js-like（纯前端浏览器 roguelike，零构建静态站）

你面对的是 **js-like** 的源码：一个跑在浏览器里的回合制 roguelike 游戏，纯 ES5 时代的
JavaScript，没有模块系统、没有打包器、没有 `package.json`，仓库根目录就是站点根目录。
一个入口 HTML 页面先加载一个自研的小型 DOM/事件工具库，再加载一个脚本装载器；装载器先去
同源取一个只有几个字的版本号文件，拿到之后按队列把大约八十个源码文件依次插进页面
（每个都带上刚取到的版本号做缓存参数），全部就位后再启动游戏。仓库里另有 `algo/`（一个
独立的算法演示页面）、`tools/`（开发期小工具）、`img/`（一百多张贴图）、`sound/`（几个
音效文件）、`ttf/`（一款等宽字体，样式表里优先用本机已安装的同名字体，找不到才回退）。

游戏本身的盘面是这样组织的：

- **开局**：先弹一个角色生成对话框，里面是一张「种族 × 职业」的图片网格，点一格就选定，
  名字栏有默认值，不必填。选定之后进入第一张地图——教学关「Beginner's dungeon」，
  60 × 20 格，角色出生在南边一条横向走廊里。地图上预先摆着：几扇关着的门、一堆金币、
  一支火把、一件衣服、一只哥布林、一只老鼠。角色出生时背包里有一小堆石头。
- **画面**：地图区上方有三个切换锚点，可以在**字符画**、**图形贴图**、**画布**三种渲染方式
  之间切；默认是画布。地图只画角色当前看得见的那一片，走过的地方会以「记忆」的形式留下
  较暗的残像，看不见的地方不画。
- **信息面**：页面左侧是一栏消息文本（游戏里发生的事都往这里写一句话），右侧是一条状态列表，
  依次是角色名、HP、Mana、回合数（Round）、当前地图名。
- **操作面**：状态列表下方是一组命令按钮，按 Movement / Interaction / Item / Magic / Info 等
  分组（连续走、上楼下楼、开门、关门、踢、聊天、搜索、拾取、丢弃、装备、投掷/射击、施法、
  存档读档等等），再下面是一个 3 × 3 的方向九宫格加一个取消键。**这两块面板在开局是隐藏的**，
  要么点页面上的 Help 锚点、要么按 `?` 键把它们显示出来。每个按钮的标签里都带着自己的快捷键，
  例如「Inventory (i)」；键盘和鼠标两条通道都能操作，方向键对应九宫格的八个方向。
- **对话框**：不少命令会弹出模态对话框（装备槽、物品列表、确认框、提示框）。对话框弹出的
  期间游戏引擎是暂停的，命令按钮会被禁用，只留对话框自己的按钮和（视情况）取消键可点；
  关掉对话框后引擎立刻继续。
- **回合**：这是一个严格的回合制引擎——玩家的每一个动作消耗一个回合，引擎同步地把这一回合里
  所有生物的动作、效果结算、状态刷新一次做完，然后等下一个输入。投掷/射击是少数几个带
  「过程动画」的动作：石头出手后是一格一格飞过去的，飞行期间引擎被锁住，落地才解锁。
- **存档**：存档走浏览器本地存储（老浏览器回退到 cookie），只有玩家主动存档时才会写。

工程就在当前工作区里，**完全离线，也完全不需要构建**：判分链路直接把仓库目录用静态文件
服务器伺服起来，再用真实浏览器打开首页、驱动界面。**没有任何网络访问**：页面里出现的外部
网址全都是文档性质的（DTD/命名空间声明、散文里的参考链接、注释里的老地址），运行期一个都
不会去取。判分环境把游戏的随机数发生器接到一个**固定种子**上（这是判分装置的既有部分），
所以每一次开局掷出来的角色属性、怪物行为、掉落判定都是可复现的：同一个操作序列两次跑出来
的盘面完全一样。请把它当成既成事实，不要改动它、也不要绕过它。

QA 收集了一批用户报告，另外附了两条内部走查时记下的疑问。下面基本按原话照录——带着他们
自己的操作步骤、噪音和猜测。把它们当起点，不要当诊断结论：

- 大部分报告描述的是真实、可复现的缺陷，每一枚都有自己的根因；根因所在的文件未必是症状
  表现出来的那个地方，同一个症状也可能有好几个候选解释。
- 至少有一条记录描述的其实是**本来就该这样**的行为。动手改之前先自己复现、先鉴别：把不是
  缺陷的东西「修」掉，一样算你弄坏了行为。
- **并非所有缺陷都有报告提及**，报告里没有全部列出。没被提到的缺陷同样在判分范围内；你在
  修别的问题时顺手弄坏的行为，也一样算你的失分。

报告与走查记录如下，顺序没有意义：

1. 「进了游戏之后键盘整个是死的：方向键不走人，`?` 出不来按钮面板，`i` 打不开背包，什么键都不响应。我一开始以为是焦点没在页面上，先用鼠标点了一下地图区域再按，还是一样。奇怪的是鼠标点是好的——把右边那两块面板用 Help 锚点调出来之后，用鼠标点按钮、点九宫格，一切正常。所以不是游戏卡了，是键盘这条路彻底不通。」

2. 「『连续走』坏掉了。我把按钮面板调出来，点 Movement 那组的第一个按钮，再点地图上东边走廊的一格，角色只往前挪了一步就停在那儿了，像被什么东西拦住一样。那条走廊我看得很清楚，直着能走六七格，尽头才拐弯；我一步一步点九宫格是能一路走到底的，只有『连续走』这个功能走一步就死。以前不是这样的。」

3. 「地图上方那三个渲染方式的切换锚点，点『图形』没有任何反应：地图不变、锚点上的当前标记也不动、控制台也没看到弹窗。我点了十几次，又试了另外一个锚点，都一样。刷新页面回来还是默认的画布渲染。看起来像是点了个死链接。」

4. 「装备好石头之后用『投掷/射击』朝东边投了一发，出手那一瞬间整个游戏就假死了：命令按钮点不动，九宫格点不动，状态栏不动，画面上连石头飞行的影子都没有。我干等了一分多钟还是死的，只能刷新页面重来。刷新之前我特意看了状态栏，回合数也没有再涨。」

5. 「状态栏里的『Round:』永远是 0。我走了十几步，还打死了一只老鼠，血条那几行（HP、Mana）和最后的地图名都会正常变化，就第四行的回合数一直钉在 0 上。我确认过不是显示延迟——放着一个小时不动它还是 0。」

6. 「刚进游戏、选完角色之后，屏幕右边一块按钮都没有，只有一个空空的九宫格框子在那儿。是不是界面没加载完？我刷新了好几次都一样，每次都得自己去点页面上那个 Help 才把按钮调出来。感觉开局就应该直接显示出来才对。」

7. 「地图大部分是黑的，只有角色周围一小片被画出来，走一步才多亮一片，走过的地方留下一层灰蒙蒙的旧图。我以为是贴图没加载出来或者渲染坏了，把三种渲染方式都试了一遍（切换那个另说，见上），每一种都是这个样子。这是故意做成这样的吗？看着像只显示了一半的地图。」

## 约束

- 本次会话里不要自己起静态服务器、不要跑任何测试或构建来自验；另有判分器会伺服仓库目录并
  用真实浏览器驱动界面。请把力气放在读代码、找根因上。
- 修复要落在根因上，不要为了绕过某条报告而加特例判断、加开关、或改判分面。
- 不要改判分链路会读的那些探针与装置文件，也不要新增全局标志、或把状态写进浏览器本地存储／
  cookie／URL 参数来「让读数变对」：判据里专门有一组检查点在看这些残留。
- 保持既有工程形态：零构建、无模块系统、无依赖管理、ES5 风格。不要引入第三方依赖，不要新增
  构建步骤，也不要为了「顺手现代化」而重写无关文件。
