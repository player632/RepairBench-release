# 修复任务：camunda_modeler_logicflowify（SolidJS + LogicFlow 的 BPMN 建模器）

你面对的是 **camunda_modeler_logicflowify** 的源码：一个纯前端的 BPMN 流程
建模器，导出面指向 Camunda 8（Zeebe）执行平台。界面用 SolidJS + TypeScript
写，画布由 LogicFlow 1.2 驱动，vite 4 打包，样式是 CSS Modules。整个应用是
经典的三栏布局：

- 左边一列可以拖出来的元素：开始节点、结束节点、任务节点、用户任务、子流程；
  拖到画布上就落下一个元素。
- 中间是画布。点中一个元素，它旁边会弹出一个小浮层，里面是「追加一个后继
  元素」和「删除」；点中空白处浮层收起。
- 右边是属性面板，内容随选中的元素类型变化。用户任务最全：General（标识、
  名称）、文档、指派（指定人、候选用户组、候选用户、到期日期、跟催日期）、
  输入、输出、任务头、拓展属性，每个区块的标题都能点开/收起，输入、输出、
  任务头、拓展属性这几个区块的标题右侧还有一个加号，用来加一行。没有选中
  任何元素时，右侧编辑的是流程本身的全局属性。
- 顶栏两个按钮：「导入」读一份 BPMN 文本画到画布上，「导出」把当前画布写回
  BPMN 文本。指派那几个字段旁边各有一个小圆按钮，用来在「普通值」和「以 =
  开头的表达式」之间切换。

工程就在当前工作区里，完全离线：依赖已经装好，`pnpm exec vite build` 会把
产物打到 `dist/`，判分链路就是伺服 `dist/` 之后用真实浏览器驱动界面。种子里
自带的 `pnpm run build` 在这个离线工作区会被 pnpm 的 ignored-builds 保护挡住
（跟你的改动无关），判分链路因此直接走 vite。没有后端，也没有任何网络访问。

QA 收集了一批用户报告，下面基本按用户原话照录——带着他们自己的操作步骤、
噪音和猜测。把它们当起点，不要当诊断结论：

- 大部分报告描述的是真实、可复现的缺陷，每一枚都有自己的根因；根因所在的
  文件未必是症状表现出来的那个地方。
- 至少有一条报告描述的其实是**本来就该这样**的行为。动手改之前先自己复现、
  先鉴别：把不是缺陷的东西"修"掉，一样算你弄坏了行为。
- 报告里**不一定提到全部缺陷**。没被提到的缺陷同样在判分范围内；你在修别的
  问题时顺手弄坏的行为，也一样算你的失分。

报告如下，顺序没有意义：

1. "我们有一批用户任务是从别处导进来的，里面到期日期、跟催日期都填得好好的
   （文件里能看见 2024-05-01T09:30:00 这种）。可在这个建模器里点开那个用户
   任务，右边『到期日期』『跟催日期』两个框是**空的**，一个字符都没有，看着
   就像日期在导入的时候丢了。更糟的是同事以为真的丢了，就在空框里重新挑了
   一个日期，结果把原来的值覆盖掉了。文件里的值其实一直都在——你们自己导出
   一次再看看就知道了。"

2. "画布上删不掉东西。我点中中间那个用户任务，旁边浮层出来了，我点『删除』，
   浮层收起来了，可节点还好好地在画布上，连着它的两根箭头也还在。我连点了
   五六次都一样。有意思的是删**箭头**是好使的：点中一根线，浮层里点删除，
   线就没了。所以只有删节点这一条路是死的。"

3. "『导出』出来的文件我们下游的工具全都打不开。Camunda 那边的导入器直接报
   文件不合法、解析不了；我们自己写的校验脚本用浏览器的解析器一读，也是同样
   的结论。用文本编辑器打开看，标签、层级、内容看着都挺像那么回事，元素一个
   不少，肉眼实在看不出哪里坏了。这个建模器早先导出的文件是能正常用的，现在
   一份都过不去。"

4. "有个特别小的文件导不进来。里面就一个开始节点、一根连线都没有——是我们
   用来做冒烟测试的最小样例。点『导入』以后画布上**一片空白**，什么都不剩，
   控制台里好像还甩了一段异常出来。稍微大一点的文件（一个开始、一个任务、
   一个结束、两根线；或者带子流程的那种）导入都是正常的，元素、连线、文字
   全都在。所以问题好像只出在『只有一个图形』这种文件上。"

5. "在右边面板里改元素的名字，画布不跟着变。我点中那个用户任务，右边『名称』
   里把 Review order 改成别的，输入框里的字是改了，可画布上那个框底下显示
   的还是老名字。要看到新名字只能导出去再导回来一次，太傻了。改『标识』那
   一栏我没敢多试，反正名称这一栏是肯定坏的：改完画布上就是不动。"

6. "『输出』区块的加号坏了。我给用户任务加一条输出映射，点『输出』标题右边的
   加号，结果**输出里一行都没多**，倒是上面『输入』区块凭空多出来一行空的。
   我一开始以为眼花，反复试了三次，每次都是这样：点输出的加号，行落在输入里。
   反过来点『输入』自己的加号是正常的，行就落在输入里。"

7. "选中一个元素以后旁边那个小浮层少了一项。以前点中一个任务节点，浮层里有
   两个图标：一个是『结束节点』（在当前元素后面追加一个结束事件，很常用），
   一个是『删除』。现在点中任务节点只剩『删除』一个，追加那一项不见了，我只能
   自己去左边拖一个结束节点再连线，多两步。还有一头更怪：我点中结束节点自己，
   浮层里反倒多出来一个『结束节点』——结束节点后面再接一个结束节点，这明显也
   不对，以前点结束节点是只有『删除』一项的。两头都跟以前不一样了。"

8. "左边那一列元素里，『子流程』那一格显示得不对：图标的位置上是英文单词
   icon 这四个字母，别的四格（开始节点、结束节点、任务节点、用户任务）都是
   正常的小图标。看着像是谁忘了把占位符换掉。这个不影响建模，拖出来的子流程
   是好的，就是左栏这一格难看，每次演示都被人问。"

9. "我们在文件里给用户任务挂了两条拓展属性（一条 region=emea，一条 tier=gold），
   导入以后右边『拓展属性』区块是空的，一条都没有，还以为导入把它们吃了。
   然后我们在这个建模器里手动加了一条拓展属性、填上名字和值，再导出——导出
   的文件里那条是在的。所以『手动加的能出去、文件里带进来的进不来』。想确认
   一下这是不是这个建模器一直以来的行为，还是最近坏的：如果是它一直就不读
   文件里带的拓展属性，那我们改流程就行，不用你们动代码。"
