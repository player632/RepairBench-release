# 我们这套后台管理系统，最近毛病有点多

各位好。这是一套用 Vue 3 + TypeScript + Vite 构建的中后台管理模板，我们内部拿它做业务后台的底座。
最近测试和运营陆续报上来一些问题，我把原话整理在下面。**请注意：并非所有缺陷都有报告提及** —— 下面这
几条是用户看得见、说得出口的部分，系统里还可能存在没有被任何人报告过的其它问题，需要你们自己在排查的
过程中一并发现和修复。修完之后，我们希望能整站恢复到「该有的行为都对」的状态，而不只是把下面这几条
逐条按下去。

## 一、用户报上来的问题（原文照录）

1. 基础列表页底下那行分页统计写的是「共 60 条」，可这个表明明有几百条数据，翻页也能翻到好几页。数字看着像是少了一个 0，是不是后端返回的总数字段取错了？

2. 基础表格那一页最右边的「操作」列整列没了，删除／编辑按钮找不到。列设置里也勾不出这一列来，像是配置丢了。

3. 左边菜单栏全变成英文／路径名了，「主控台」显示成 dashboard_console、「基础列表」显示成 basic-list，看着像国际化配置掉了一半。

4. 指令示例页那个「防抖测试」按钮，连点三下会弹三条一样的提示，防抖根本没起作用，看着像是点了三次就触发三次。

5. 基础列表页上面那个查询表单，点了「重置」以后别的框都清了，只有我在「姓名」里打的字还留在那儿，重置像是没重置干净。

6. 从基础列表点「编辑」进到详情页以后，左边菜单没有任何一项是高亮的，看不出自己现在在哪个栏目下面；回到列表页倒是正常。

7. 面包屑少了一级：进「工作台」的时候上面只显示「工作台」，前面的「Dashboard」那一层不见了；别的页面也都是一样少最前面那一级。

## 二、还有两条我们拿不准是不是问题，也一并贴出来

8. 「关于项目」页面里那个「最后编译时间」每次构建都不一样，刷新一次部署就变一次，我们这边没人改代码它也在动。是不是时间戳有 bug、或者哪里缓存没清干净？要不要把它固定下来？

9. 主控台「销售额」那张卡片里的进度条显示百分之四五万（4 万多%），条子直接顶满还溢出，数字也长得离谱。是不是百分比算错了、或者数据格式没对上？

🔴 关于第 8、9 两条，请**先判断它们到底是不是缺陷再动手**。我们的经验是：看起来最像 bug 的东西不一定
是 bug，而真 bug 常常藏在没人报的地方。如果某一条其实是这套模板**本来的设计**（比如某个数字就是构建时
生成的、或者某个值本来就是演示数据随机造的），那就请不要去「修」它 —— 把它改成固定值反而会让原本正常
的行为坏掉。请把你们的判断写在提交说明里。

## 三、复现与验收环境

- 视口：**1440 x 900**，语言 en-US，时区 UTC。所有页面都在这个窗口尺寸下复现和验收。
- 路由是 history 模式，直接访问深层地址（例如主控台、工作台、基础列表、基础表格、指令示例、详情、关于
  项目、内嵌文档）都应该能正常打开，不需要先回到首页再点进去。
- 登录态：验收环境会自动带上有效的登录凭证，你们不需要去改登录逻辑，也不要把任何状态写进浏览器本地存
  储或全局变量来「记住」修复结果 —— 每条验收都是在干净的新上下文里独立跑的。
- 这套系统在验收时是**完全离线**的：所有接口数据都来自项目自带的 mock，不发任何外网请求。请保持这一
  点 —— 不要引入任何外部 CDN、外链图片、外链脚本、外链字体，也不要加埋点或统计。如果排查过程中发现某
  个页面还挂着外部地址，把它改成本地资源或空文档即可，不要让它在离线环境里挂着转圈。
- 项目自带的构建产物目录里可能残留着上一次构建的旧文件，那些旧文件**不代表**你们改完之后的真实效果；
  验收前会重新构建，请以重新构建出来的结果为准。

## 四、交付要求

- 请直接修改源码，不要改验收脚本、不要改 mock 数据来「让现象消失」、不要靠硬编码字符串把某一条按下去。
- 一条问题可能牵扯到多处表现（例如菜单高亮、面包屑层级、分页数字），请按**根因**修，不要按现象逐条打补丁。
- 修完之后请自己把上面 9 条逐一复现一遍，并额外确认这些没有被动到：表格行数、表格列顺序、表单字段数量、
  页面标题、菜单项数量与展开层级、卡片标题、按钮的可用／禁用状态切换、以及各页面之间的跳转。
- 如果你们认为某一条报告的现象其实是正常行为，请在提交说明里写清理由；我们不会因为有报告就一定要你们改。
