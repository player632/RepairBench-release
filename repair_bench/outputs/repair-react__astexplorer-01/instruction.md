# AST Explorer 内网部署：使用者反馈汇总（请修复）

我们把这个在线语法树浏览工具搬到内网，给代码评审的同事当「贴一段代码、看它被解析成什么结构」的
桌面工具用。上线两周，收到一批反馈。下面这些都是他们在浏览器里**实际看到的现象**，我按收到的先后
原样转述，没有替他们做任何技术判断，也没有去核对代码；其中混着两条我们自己也拿不准算不算毛病的
抱怨，请自行甄别。

> ⚠️ 先说一句要紧的：这份反馈**并不完整**，并非所有缺陷都有报告提及。有些毛病没人反馈，
> 但验收的时候照样会检查。请你自己把整个界面走一遍做个体检，别只照着下面这七条改。

## 一、明确报上来的七条

1. 右边输出区上方有「Tree / JSON」两个切换按钮。点了 JSON 之后，那个按钮自己确实变成了选中的样子，
   可下面的内容还是原来那棵树，怎么点都切不过去。刷新页面重来也一样。

2. 左边示例代码（一个 tips 数组和一个打印它的函数）在树里展开以后，想再点一下节点名字把它收起来，
   它不收——得反复点好几下，有时候干脆就收不回去了，只能刷新页面。

3. 树里面的字符串值现在都不带引号了。以前像 `"module"` 这种是会带着一对双引号显示的，
   现在光秃秃一个词，跟节点类型名混在一起，一眼看不出哪个是字符串。

4. 在上面那个转换菜单里选了 prettier，工具栏上的开关图标没有变成「已开启」的样子，
   页面下方也没有出现写转换代码的那块面板，看着就像点了没反应。

5. 中间那条竖直分隔条，拖到位、鼠标也松开之后，左右两块面板还在跟着鼠标继续变宽变窄，
   非得再去点一下别的地方它才停下来。

6. 鼠标划过树里的节点（比如那个变量声明节点），左边源码里对应的那一段不再高亮了，
   以前是会浮起一层底色的，评审的时候靠它对位置，现在没了。

7. 打开解析器设置（齿轮按钮），把 `locations` 勾上，点 Close 关掉；再点齿轮打开，刚才勾的又没了，
   回到没勾的状态。每次改都要重勾一遍，很烦。

## 二、我们也拿不准算不算毛病的两条

A. 页面最底下那行「Built with React, Babel …」后面跟着一串 `@@COMMIT@@`，看着像是模板变量没被替换、
   构建脚本坏了。这个要不要修？

B. 键盘布局那个菜单里，除了 default 还列着 vim / emacs / sublime 三项。我们内部没人用得上，
   看着像是早就废弃的死代码，能不能直接删掉让菜单干净点？

## 三、验收口径

- 第一部分 1~7 条描述的现象，修完之后都不应再出现。
- A、B 两条**如果本来就是正常行为，请保持原样**，不要为了「看起来更干净」去动它们；
  验收会反过来检查这两处的既有行为有没有被破坏。
- 不要去改构建产物目录里的东西，也不要靠给页面加测试专用标记、加特判分支来让检查通过。
- 界面上的文字、菜单项、默认解析器、示例代码这些都应保持原样；工具整体仍然是纯前端、
  离线可用，不要引入任何新的外部请求。
