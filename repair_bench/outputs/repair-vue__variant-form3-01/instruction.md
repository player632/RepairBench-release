# 我们那个拖拽式表单设计器，最近好几处不对劲

我们内部用的是一套开源的低代码表单设计器（Vue 3 + Element Plus + Vite 那一套，版本号
3.0.10），既能拖拽设计表单，也能把设计好的表单渲染出来。构建是 `npm run build`（就是
`vite build`），产物落在 `dist/`，伺服的也是这个目录，所以改了源码必须重新构建才看得见。

界面大致是这样：最左边一竖排小按钮——撤销、重做、PC／Pad／H5 三种设备宽度、组件层次
结构树；挨着的是分组的组件库，容器组件那一组本来只有栅格、表格、标签页、卡片这 4 个，
字段组件那一组有 23 个（单行输入、多行输入、计数器、单选、多选、下拉、日期、上传等
等）。中间是画布，从组件库拖一个进来就生成一个字段，点一下选中它，字段右上角有「选中
父组件」「上移组件」「下移组件」「移除组件」这几个动作。最右边是四个页签：组件库、表单
模板、组件设置、表单设置——组件设置里是选中组件的属性（唯一名称、标签、字段标签对齐、
默认值、占位内容、必填字段、校验、只读／禁用／隐藏、自定义 CSS 样式等等），表单设置里
是整张表单的配置（标签位置：左边／顶部，等等）。顶部一排按钮：清空、预览、导入 JSON、
导出 JSON、导出代码、生成 SFC。点「预览」会把当前表单渲染进一个对话框，底部有获取数
据、重置表单、禁用编辑、恢复编辑、关闭。

**离线约定**：这个包在浏览器里跑，页面不许向外部网络要任何东西。种子原本会从几个跨域
CDN 取模板缩略图、代码编辑器的动态资源和代码美化脚本，随包附带的适配把它们统统改成了
同源的惰性占位路径：模板卡片的预览图因此是空白占位、代码美化那条路走不通（「生成
SFC」本来也没人用）。这两点都是预期之内的，别去替它们造数据，也别当成缺陷去修。

**先把话说在前面**：下面这些只是我们几个人平时用得到的部分，**并非所有缺陷都有报告
提及**。有些毛病我们可能压根没注意到，或者不知道该怎么形容，甚至根本不知道那是个毛
病。所以请你们自己把整套东西从里到外过一遍，别只盯着我列出来的这几条改；修别的问
题时弄坏的行为，同样会算在你们头上。

## 我们确实碰到的问题

1. 删掉画布上的一个字段以后，画布里什么都不再是选中状态了，右边的组件设置面板跟着
   变空。以前删完会自动选中旁边那个字段，设置面板还能接着改下一个。

2. 预览里的栅格布局塌了。把两个字段放进栅格容器（一行两列那种），设计画布上看着还
   是左右两列，点「预览」以后对话框里那一行栅格却没了，两个字段竖着排成一列。

3. 改组件的「唯一名称」时，明明没有跟别的组件重名，却弹一句名称已存在的提示，名字
   还被退回去。以前改成一个没人用过的名字是直接生效的，只有真撞名才该拦。

4. 表单设置里把「标签位置」从「左边」改成「顶部」，画布上标签确实跑到上面去了；然后
   点「清空」重新开始，画布上重新拖进来的字段标签还是在上面，回不到左边——那次清空
   像是没把表单配置真的落回默认值。

5. 左边组件库「容器组件」那一组里多出几个不该给用户的条目：栅格列、单元格、选项卡页
   这种本来只是容器内部零件的东西，现在跟栅格、表格、标签页、卡片一起列出来，还能拖
   到画布上。以前那一组只有 4 个。

6. 撤销／重做的行为不对。改三处，撤销两次，再改一处新的，这时候「重做」本应该变灰
   （后面那几步已经被新改动顶掉了），可它还能点，点下去会把已经作废的历史又放回来。

7. 在组件设置的「自定义 CSS 样式」里写一段样式并保存，那段样式会被插两遍：页面的头
   部里出现两份内容一样的自定义样式节点，再保存一次还会继续叠。以前是同名的一份，改
   一次就替换一次。

## 有几处看着别扭，但我们确认过是正常的，别去「修」

- 「清空」按钮点下去直接就清空画布，不弹二次确认框。我们一开始以为确认框坏了，核对
  过种子自己的行为以后确认它本来就没有确认框，别给它加一个。
- 新拖进画布的字段，默认标签不是中文，而是该字段类型的英文名（单行输入、多行输入、
  计数器各有各的）。这是种子自己的默认值，别去把它们汉化。
- 组件库右边「表单模板」页签里那 8 张模板卡片的预览图是空白占位，点「载入模板」也不
  会有内容——这是上面那条离线适配的正常结果，别去补图、补数据，也别把卡片删掉。

## 修的时候请注意

- 页面依然不许向外部网络要任何东西，跨域请求数必须是 0；也不要在页面里留任何跨次运
  行的全局残留（本地存储、地址栏、挂在窗口上的变量都算）。
- 撤销／重做走的是应用自己的历史栈，别靠清历史、禁用按钮或者把按钮藏起来「修」掉症状。
- 唯一名称的校验要保持「真撞名才拦」的原意，别把校验整个关掉，也别让它对不撞名的改
  动报错。
- 画布的拖拽、选中、上移下移、字段增删这些行为本身是好的，别为了让某条报告闭环把它
  们关掉或者改弱。
- 容器组件那组多出来的条目，正确的修法是把内部零件挡在设计器之外，不是把整组容器组
  件删掉。
- 修完以后 `npm run build` 必须还能过，产物还得照常落在 `dist/`。
