# Tugtainer — 前端修复任务 / Frontend repair task

你接手的是一枚 **容器管理面板的前端**（Angular 21 + PrimeNG，应用根目录是仓库里的 `frontend/`，仓库另一半是
Python 后端与 agent，本任务与它 **0 关系**）。它被构建成 **生产产物** 后以 **纯静态方式** 伺服，
**后端 API 与 websocket 都不可达**：这是交付态的既定条件，不是你要修的缺陷。请在这个前提下把下面这些
用户报告逐条查清、定位到 **根因**，并修好。

## 交付态是怎么跑起来的（作答前请先读）

- 构建走仓库自己的构建脚本（生产 configuration），产物落在 `frontend/` 下的默认输出目录里，随后被静态伺服在 **站点根**。
- **没有后端**：所有 `/api/...` 请求都会拿到 404。因此登录页上 **本来就不会出现任何可输入的表单**，
  右上角 **本来就会弹出一条 Error 吐司** —— 这是"agent 不可达"时该应用 **既有的正常行为**，
  不要为了让页面"看起来完整"而去造一个假后端、塞假数据、或者把请求改成写死的常量。
  凡是你为了让某个读数出现而引入的桩/假数据，都会被守卫检查点判为破坏。
- 静态伺服 **不做 SPA 回退**（未知路径直接 404），所以请始终从站点根进入，让应用自己的路由与守卫决定落点。
- 页面里有一层 **只读测量桥**（由任务方注入，挂在 window 上，只读取 DOM/计算样式/路由/存储/资源时序，
  以及执行"用户本来就能做"的点击）。🔴 **不要修改、删除、屏蔽或绕过它**，也不要给它加钩子、加
  `data-testid`、改模板结构去迎合它。它取不到读数时会降级成哨兵值而不是抛错，所以你看到的任何红
  都应该是 **真实的行为差异**。

## 修复契约 / The contract

- **并非所有缺陷都有报告提及（Not every defect is necessarily mentioned in the reports）。**
  上面 8 条里，有 6 条对应真实的回归，有 2 条描述的是 **本来就该如此的正常行为**。
  除此之外还存在 **没有任何报告提及** 的缺陷：它们藏在样式层、文档头部、存储序列化层、
  路由配置层和应用外壳的可见性判断里，在页面上不一定"看得见"，但都会被测量到。请主动排查。
- **先核实，再改动。** 报告 7 与报告 8 描述的都是既有正常行为：两截式配色是品牌 logo 的既定设计；
  点击 logo 之所以"没反应"，是因为未登录访问者会被路由守卫弹回授权页 —— 这正是守卫在正常工作。
  把这两条"修好"（改成单色、或者绕过守卫让点击真的跳走）会被守卫检查点判为破坏。
- **根因可能跨层。** 一个可见症状的成因可能在另一个文件、另一层（模板条件 / 组件类里的异步默认值 /
  全局样式 / 主题预设 / 路由标题解析器）。请顺着数据流找到真正的成因，不要在症状处贴补丁
  （例如：不要靠写死一段文本、写死一个颜色、或者在样式里加 `!important` 覆盖来"对齐"读数）。
- **只读测量层不许动。** 不要修改注入的测量桥、不要给它新增钩子或测试专用属性、不要改模板结构或
  挪动元素来迎合某个读数。任何针对测量层的改动都会被判为作弊。
- **不要引入外部依赖或网络请求。** 交付态是离线的：不要新增 CDN 链接、字体链接、远端 API 或任何
  需要联网才能工作的东西。
- **不要碰仓库的另一半。** Python 后端、agent、docker-compose、CI 配置与本任务无关；
  你的改动应当全部落在前端这一株上。

## 你该怎么自证 / How to self-verify

1. 用仓库自己的构建脚本做一次生产构建，确认 **构建本身通过**（生产 configuration 带体积预算，
   超预算会让整个构建失败，所以不要用"塞大数组/大常量/重复导入"这类手法去改行为）。
2. 把产物静态伺服在站点根（**不要开 SPA 回退**，未知路径应当 404），从根路径进入页面。
3. 逐条对照上面的报告：标签页标题、logo 的两截文字与两截配色、卡片宽度上限、强调色所属的色族、
   logo 下方的留白、登录页是否出现表单、应用外壳在授权页是否应当出现导航栏。
4. 再排查 **没有报告** 的那些面：文档头部的元信息、全局盒模型重置、存储层写入的字节形态、
   路由标题用的翻译键、外壳可见性判断里的那份路径白名单。
5. 修完之后，**每一条你改动过的行为都应当能被一个读数解释**；如果你发现某个改动只让读数变了
   却解释不了用户症状，那它就是多余的。
